# 脚本制御の戦闘: 調査・設計・判断 (#741 / #863)

- ステータス: **段階 1 実装済み（#741 の全項目＋#863 のうち土台で自然に入るもの）**。残りは下の「範囲外」
- 利用ゲーム: sit-by-me（冒頭の劇戦闘の中断・能登の負けイベント＋途中参戦・体内の逃げるイベントバトル・心臓の HP0 からの復活）
- 仕様（書式）は `docs/spec/markdown-v0.1.md` の「脚本制御の戦闘」。ここは**なぜそうしたか**

## 1. 調査（着手時の現状）

- 戦闘は `BattleEngine`（自由な状態機械）＋ `BattleScreen`。フィールドからは `fieldBattle.ts` の `openFieldBattle` で開き、終了時に `BattleResult`（#831）をホストの `onBattleEnd` へ渡す。脚本から勝敗・進行を固定する手段・戦闘中に台詞を挟む手段・結果を脚本側へ返す手段は無かった。
- 終了は `victory` / `defeat` / `escaped` の 3 つだけで「中断」を表せない。終了判定は `advanceAfterPartyAction` / `runEnemyTurn` / `checkEnd`（ATB）に分散していた。全体のターン番号を持たない（敵 AI は敵ごとの行動回数 `acted`）。
- HP の書き込みは `applyDamageToHp`（#877）が基本だが、即死・builtin・状態の満了が `hp = 0` を直接書く経路が 3 つ、負の回復が HP を減らす経路が 1 つあった。
- **ノベル側（`[フラグ:]` `[条件:]` `[ジャンプ:]`）に戦闘の開始・終了のディレクティブは無い**。プロジェクトはノベルか RPG のどちらかで再生され（`PlayerScreen`）、RPG のイベント（`[イベント]` / `[トリガー]`）は Dialog / Narration / NpcMove / Wait だけでフラグを持たない。既存の「つなぎ目」は `BattleResult` をホストへ返す口だけだった。→ 戦闘結果をフラグに反映するのはホストの責務とし、エンジンは「どのフラグをどう立てるか」を結果に載せて返す。`NovelRenderer.ts` は変えない。

## 2. 設計の柱

1. **宣言（markdown）で書ける**: マスターの新ブロック `[戦闘 id]`（`[特技]` `[状態]` と同じ流儀。parser は `キー: 値` を生文字列で透過し、runtime が解釈。不正行は警告して無視）。ルール行は `enemyAi.ts` の `行動:` と同じ `キー=値`・条件の `,` AND。
2. **エンジンの純粋性を保つ**: 脚本は宣言（データ）として `BattleEngineOptions.script` で受ける（`skills` / `statuses` と同じ「呼び出し側が渡す宣言」）。解釈・条件評価・「いま発動するルール」の決定は純粋関数モジュール `battleScript.ts` が行い、エンジンは**行動の境目**で `scriptStep` を呼んで決定を受け、自分の操作（台詞・参戦・復活・逃走・強制終了・HP 下限の付け外し）で適用するだけ。乱数は使わない。
3. **決定論（ADR 0002）**: 脚本の状態は `BattleState.script`（経過ターン・発動済みルールの添字・参戦した味方の id・逃げた敵の添字。数値・文字列・配列だけ）。`script` を渡さない戦闘は状態の形・ログ・乱数の消費まで従来どおり（テストと、既存のハーネスの族のバイト一致で確認）。
4. **膠着しない**: 倒れない・倒せない状態を作る `下限` は便利だが、決着しない戦闘を作りやすい。`固定:` は上限ターン（既定 99）で必ず終了する形に展開し、手書きの `下限` に終了条件が無ければ読み込み時に警告する。検証ハーネスの新しい族は「必ず決着する・固定した結果で終わる・ターン上限を守る」を機械的に見る。

## 3. 意味論の判断（おすすめ案として採用。異論があれば差し戻し）

| 論点 | 採用 | 理由 |
|---|---|---|
| 「ターン」の数え方 | 経過ターン数。従来ターン制は「味方の行動 → 敵の行動」の 1 巡、ATB は味方の行動 1 回 | 従来ターン制と ATB で「N 回行動したら」の意味が揃う。敵 AI が全体のターン番号を使わず個別の行動回数を使う設計（`docs/design/enemy-ai.md` §3.2）とは別に、脚本は戦闘全体の進み具合を見る必要があるので、脚本のある戦闘だけ数える |
| ルールの発動回数 | 1 回だけ | 繰り返しは条件の `ターン=N` で書ける。無限ループ・イベント洪水を構造的に作らない |
| 評価のタイミング | 行動と行動の境目で、勝敗の判定より前 | 復活すれば全滅にならない。開始時に敵が全員逃げれば勝利になる（進行不能にならない）。ATB は `tick` 内の判定にも入る |
| 勝敗固定の作り方 | 「HP 下限」＋「上限ターンでの強制終了」の組み合わせ（`固定:` は展開） | 勝ち・負け・中断を別々の機構にせず、小さな部品（下限・終了）の合成で表す。手書きでも同じ部品が使える |
| 中断 | 新しい終了種別 `interrupted`（`BattlePhase` / `BattleResult.outcome` / `onClose` / `FieldBattleTransition`） | 勝敗にも逃走にも混ぜない。ホストが暗転・次の場面へ分岐できる。逃走と同様に勝敗の待機なしで閉じ、報酬は victory のときだけ |
| 負けイベントの `敗北` | `defeat` のまま、結果に `script` が付く | ゲームオーバーにするかはホストの判断（`script` の有無・`id`・`flags` で区別できる） |
| 途中参戦の人数 | 初期編成は `味方:`、参戦者は初期編成にいない `[パーティ]` 全員（`参戦:` が id で引く） | 1〜4 人で変わる戦闘（#863）を宣言で書ける。`BattleScreen` は `refresh` で増えた味方の絵・行・ATB 棒を足して配置し直す。**side レイアウトだけ**（front は先頭 1 人しか描かないので、参戦しても操作・表示できず、ATB では入力待ちを作ってしまうため扱わない） |
| 復活 | 対象が HP 0 のときだけ発動（条件が真でも保留）。HP/MP 指定・状態の付与（宣言の無い状態は警告して付けない）。発動は 1 回。**イベントであり、勝敗は保証しない**（復活後は操作がユーザーに戻り、勝つか負けるかはユーザー次第）。ATB はゲージ 0 から溜まり直し、キューも整合する | 「HP0 にされたあと脚本で復活」を全滅判定より先に処理して、ゲームオーバーにしない。状態の付与は #870 の `[状態]` に乗る |
| 逃走 | 敵の HP を 0 にして消す（経験値・ドロップなし）。倒した扱いにしない。死亡時・反撃は発動せず（`enemyMemory.died` を立てる）、敵の蘇生（`仲間単体`）の対象にもならない | 「倒せない小さな敵が最後に必ず逃走」。`下限` で倒れない敵＋盾役の中ボスの組み合わせを同じ戦闘で書ける |
| 戦闘中の台詞 | ログに積み、FF 式は `notice` の窓に出す。字数に応じて見せる時間を延ばす（上限 3.5 秒） | 既存の窓・ログの仕組みを増やさない。開始と同時に積んだ台詞は、作り直した画面が過去を再生しない規約の例外として最初に読ませる |
| にげる禁止 | `にげる: 不可`（押しても知らせだけ。ターンも乱数も使わない） | 劇・負けイベントで逃げられると脚本が崩れる。連打しても進行しない・詰まない |
| 結果のフラグ | `勝利時` などの宣言を `BattleResult.script` に載せて返す。エンジンは保存しない | ノベルのフラグ状態はホストの責務（上の調査）。値の種類は `[フラグ:]` と同じ |
| 戦利品（#831）との同居 | `BattleResult` に `loot` / `items`（戦利品）と `script`（結果フラグ・次のイベント）の両方が載る。`onBattleEnd` もイベントを待つ Promise も同じ結果を受け取る | 戦利品は勝利の瞬間のドロップと、盗めた分（逃走・中断でも失われない）。脚本の宣言は戦利品の有無に影響しない |
| 開始 | `[イベント]` に `[戦闘: id]`（`EventCommand::Battle`）。`次=` のイベントへ分岐し、現在のイベントの残りは捨てる | RPG 側の既存の「シーン」はイベント。負けた後に「勝った前提」の台詞が続かないようにする。連鎖は 32 回で止める |

## 4. 実装の要点（保守向けの記録）

- `battleScript.ts`: `parseBattleScript`（解釈・警告・`固定` の展開）/ `nextScriptAction`（宣言順に未発動で成立する 1 つ）/ `computeFloors`（条件が真の `下限` から者ごとの下限）/ `resultFor`。
- `battleEngine.ts`: `scriptStep` は `checkEnd`（ATB の判定・非 ATB の味方の行動後）と `runEnemyTurn` の終わり（ターン計上のあと）、コンストラクタ（脚本のある戦闘だけ開始時の判定）で呼ぶ。`hpFloor` は `applyDamageToHp` / `knockOutHp`（即死・builtin・状態の満了の共通口）/ 負の回復が尊重する。ATB の tick で、並べる前にゲージが満タンのままかを見る（同時に満タンになった味方を先に敵が倒し脚本が復活させたとき、ゲージ 0 のままコマンド待ちに並ぶのを防ぐ。復活が無い戦闘は従来と同一）。
- `fieldBattle.ts`: `buildScriptedBattle`（宣言から敵・初期編成・脚本・参戦者を組み立てる純粋関数）/ `openFieldBattle` の `scripted`。`TopDownRenderer.startScriptedBattle` は結果で解決する Promise を返し、`EventRunner` の `Battle` コマンドが待つ。`load()` / `destroy()` の強制終了では解決せずイベントごと捨てる。
- 敵の組み立ては `encounter.ts` の `buildEnemyEntities`（`rollEncounter` と共有）。

## 5. 範囲外（Issue に残す）

- **メッセージ＋パラメーター強制の一般形**（#741 段階 2）: 戦闘中のイベントは「メッセージを出し、対象の HP/MP/状態を指定した値に強制する」ものと捉える。`復活` はその 1 例（HP0 の味方に限る）で、生きている者の HP/MP の書き換え・状態の付与/解除を 1 つの種別（例: `強制: 対象= HP= MP= 付与= 解除= 文=`）として足す設計案は、下限・上限・倒れた者の扱い・ATB のゲージ/キュー・1 回発火・ハーネス不変条件を同じ型で揃える必要があり大きいため、段階 2 に分けた。
- 戦闘ごとの固定スキル・魔法の付与（劇戦闘のフレア・メテオ級）: #875（味方のアビリティ定義と戦闘単位の一時付与）が土台。付与の指定を `[戦闘]` に書く口は #875 の後。
- 復活後に「属性相性を上回る」（火が水に勝つ）ための相性・属性の書き換え: #875 / #876 と合わせて設計する。現状は復活で HP/MP を戻し、`付与=` で宣言済みの状態を付けるところまで。
- 暗転中の音声のみ流す演出: 演出・音は host 側（`battle_transition: ff` / `ff-mosaic` の黒の間 `interlude` フックと `BattleResult.script` で組める）。
- ノベル側ディレクティブとの統合（ノベル／RPG の合流）、raycast 表示でのイベント実行。
- 脚本で敵を増やす・形態を変える（#888）、割り込み（#878）。
