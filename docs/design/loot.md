# 敵の戦利品（ドロップ・ぬすむの通常枠とレア枠）と戦闘後の受け渡し: 設計 (#831)

- ステータス: **段階1 実装済み**（土台＋最小の機能セット）。段階2 は Issue #831 に残す。書き方（markdown / 効果 DSL）は `docs/spec/markdown-v0.1.md` の「戦利品」「ぬすむ（`steal`）」
- 利用ゲーム: sit-by-me（敵ごとのドロップ・ぬすむ通常枠/レア枠、ぬすむの刀、ジョブによる強化）。エンジンは汎用のまま、ゲーム固有の語彙を持たない
- 関連: #830（戦闘の開始と終了の画面遷移）、#875（ぬすむ手段＝アビリティ。今の `わざ:` ＋ `[特技]` で書ける）、#876（ジョブによる修飾。加算の口だけ用意）、#870 / #872（確率・頭打ちの考え方の元）、ADR 0002（決定論的状態）

## 1. 要件

1. 敵定義にドロップ（確率つき）・ぬすむ通常枠・ぬすむレア枠を足す。ゲームごとに任意。書かない敵は従来どおり。id は呼び出し側が決める
2. 戦闘の結果として獲得した戦利品をホストへ渡す。**エンジンは所持品を保存しない**（中間状態を GameState に持たない）
3. 「ぬすむ」をアビリティとして実行できる。成功率・通常枠とレア枠の確率・盗み済みの扱いを設定できる
4. 戦闘終了の画面遷移（#830）が戦利品の画面を挟めるよう、結果を渡す
5. ぬすむの変種（T1 ぶんどる＝盗みと同時に攻撃／T2 成功率が上がる／T3 レア枠限定／T4 複数回など）を**設定で表せる**

## 2. 現状（実装前）

- 戦利品は `exp` / `gold` のみ。`handleVictory` が合計を `BattleState.earnedExp/earnedGold` に入れてログに出すだけで、ホストへ渡す口は無かった（`onClose(outcome)` は勝敗だけ）
- 所持品・お金・装備(#207)の保存はエンジンに無い（`battleSample` / `fieldSample` の `items[].count` は戦闘ごとに設定から始まる試作用）。したがって「ホスト」は呼び出し側のゲーム

## 3. 設計と判断

| 論点            | 採用                                                                                                                                                                                                                                     | 理由                                                                                                                                              |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 宣言の置き場    | `[モンスター]` に `ドロップ:` / `ぬすむ:` / `ぬすむレア:` / `ぬすむ回数:`。parser は生文字列で透過（`MonsterDef.loot`）、解釈は `loot.ts`                                                                                                | `行動:` `反撃:` と同じ流儀。語彙の拡張で Rust・wasm を作り直さずに済む。`Event` 列挙の大きさを抑えるため `Box<MonsterLoot>` にまとめた            |
| 1 行の書式      | `<id> [確率=P] [個数=N]`                                                                                                                                                                                                                 | 効果 DSL の `確率=` と揃える。id はゲームが決める不透明な文字列（アイテムマスターに無くてよい）                                                   |
| ドロップの抽選  | 勝利の瞬間・敵の並び順・行ごとに独立。確率 100/0 は乱数を使わない                                                                                                                                                                        | 決定論的（注入 rng のみ）。宣言の無い戦闘は乱数を 1 回も使わない（旧挙動不変）                                                                    |
| ぬすむの手段    | 効果 DSL の動詞 `steal`（呪文・特技〈わざ〉の `効果:` に書く）                                                                                                                                                                           | アビリティ定義（#875）を別に作らずに済む。刀固有・2 人まで・装備中だけ、といった制限はゲーム側（パーティの `わざ:`）で表せる                      |
| 抽選の流れ      | 成功判定（`確率=`）→ 枠の決定（`レア率=`）→ 枠の中の行を先頭から順に判定                                                                                                                                                                 | FF の「盗む成功率 → レア/通常 → 品」。失敗しても在庫は減らない                                                                                    |
| レア率の既定    | `両方`: 12.5%（FF の 1/8）、`枠=レア`: 100%                                                                                                                                                                                              | T3「通常枠を捨ててレア枠の確率を上げる」を、`枠=レア` で素直に書けるように（レア率を書けばその確率で当たり、外れは失敗）                          |
| 盗み済みの扱い  | 敵ごとの `ぬすむ回数`（既定 1＝FF 同様、盗むと空）。`無限` も可。失敗は数えない                                                                                                                                                          | sit の論点「盗める回数・敵ごとの在庫の上限」を設定可能に。枠ごとの在庫などの細かい区別は段階2                                                     |
| T2 成功率の加算 | `BattleEntity.stealChanceBonus` / `stealRareBonus`（点）。**加算で 99% を超えて上がることはないが、元から 99% 超の値は下げない**（`MAX_STEAL_CHANCE`）                                                                                   | `statusChanceBonus` と同じ型。sit 側で「99% 頭打ちを当てるか」が未決なので、1 か所の定数で後から変えられる。`確率=100` は加算が載っても必中のまま |
| T1 ぶんどる     | `steal ぶんどる=min..max [type=]`。盗みのあとに `damage` と同じ評価器でダメージ（成否に関わらず）                                                                                                                                        | FF6 のぶんどる（盗みと同時に攻撃）。新しいダメージ規則を作らない（相性・上限・反転が自動で効く）                                                  |
| T4 複数回       | `steal 回数=N`（`damage` の `回数=` と同じ 1〜99 の規則）。盗める回数に達したら止まる                                                                                                                                                    | 既存の語彙の再利用                                                                                                                                |
| 盗んだ品の扱い  | 盗んだ時点で `BattleState.loot` に積み、逃走・敗北でも結果に残る。ドロップは勝利時のみ                                                                                                                                                   | FF では盗んだ品は即座に手に入る。敗北後に捨てるかはホストの判断                                                                                   |
| 受け渡し        | `BattleEngine.getResult()` → `BattleResult { outcome, exp, gold, loot, items }`。`BattleScreen.onClose(outcome, result)` → `openFieldBattle.onClosed(outcome, result)` → レンダラー `setBattleEndHandler` → `RPGPlayer` の `onBattleEnd` | 既存の onClose/onClosed の流れに引数を足すだけ。GameState に持たない                                                                              |
| #830 との接続   | `battle_transition: ff` では畳む瞬間（黒を経由した最も暗い瞬間）にハンドラが呼ばれる                                                                                                                                                     | ホストが暗転の間に戦利品の画面を挟める。標準の戦利品画面は段階2                                                                                   |
| 戦闘中の表示    | ログに「〇〇 を ぬすんだ！」「〇〇 を てに いれた！」。HP が動かないので MISS 数字は出さない                                                                                                                                             | 既存の勝利メッセージ・結果待機（#745）の流れに乗る                                                                                                |

## 4. データの流れ

```
[モンスター]  ドロップ:/ぬすむ:/ぬすむレア:/ぬすむ回数:
  → parser（生文字列。MonsterDef.loot）
  → encounter.ts / startTestBattle の lootField → BattleEntity.loot
  → BattleEngine（parseLootSpec で解釈。ドロップ = victory の瞬間、ぬすむ = EffectContext.steal）
  → BattleState.loot（獲得順の事実の列）
  → getResult() → BattleScreen.onClose(outcome, result) → fieldBattle.onClosed → レンダラーの onBattleEnd ハンドラ → ホスト
```

## 5. 検証

- 純粋関数（`loot.ts`）・DSL（`spellDslSteal.test.ts`）・エンジン（`battleEngineLoot.test.ts`）・配線（`fieldBattleLoot.test.ts`）・サンプル設定（`public/battle-sample/loot.json`）
- 検証ハーネスの族 `loot`（`steal` の全パラメータ × 敵の宣言 × 使い手の加算 × 敵の HP × ターン制/ATB）と不変条件 `loot-invariant`（宣言した品だけ・枠の印・盗めた回数の上限・個数・ドロップは勝利のみ・順序）。`HARNESS_SKIP=loot` で既存族の `report.md` / `failures.json` が従来とバイト一致
