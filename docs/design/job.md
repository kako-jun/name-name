# ジョブ（職業）: 設計 (#740)

- ステータス: **段階1 実装済み**（土台＋最小の機能セット）。段階2 は Issue #740 に残す。書き方は `docs/spec/markdown-v0.1.md` の「ジョブ」
- 利用ゲーム: sit-by-me（全員が 3 つの現実の職業を持ち、フィールドのメニューからいつでも転職する）。エンジンは汎用のまま、ゲーム固有の語彙（職業名・人数・解放時期）を持たない
- 関連: #207（装備。`装備時` の書式と属性の層を共有）、#889（魔石。同上）、#876（パッシブ修飾層・タグ × タグの変換ルール・刀 × ジョブのプリセット）、#738（章をまたぐ状態＝現在のジョブの保存）、#880（メニュー UI）、ADR 0002（決定論的状態）

## 1. 要件（sit-by-me の決定から）

1. ジョブは**アビリティを変化させるパッシブ（バフ程度）**で、アクティブなコマンドを持たない。固有コマンド（調合・あやつる等）は魔法体系へ統合する見込みなので、ジョブに持たせない
2. ジョブは宣言（markdown）で書け、味方ごとに就けるジョブを持つ。転職はフィールドから（戦闘中の切替は後の段階）
3. ジョブを宣言しない戦闘は、乱数の消費を含めて従来と同一

## 2. 設計と判断

| 論点 | 採用 |
|---|---|
| 宣言 | `[ジョブ id]`（`名前` / `説明` / `装備時` / `属性`）。`装備時` と `属性` は魔石・装備品と**同じ書式・同じ解釈器**（`parseStatBonus` / `collect_elements`）。新しい書式を作らない |
| 就けるジョブ | `[パーティ]` の `ジョブ:`（カンマ区切り・複数行可・先頭が最初のジョブ）。同じジョブを複数人が持てるかの検査はしない（「4 人でかぶらない」は作品側の運用） |
| 現在のジョブ | 入力 `roster.currentJobs`（味方 id → ジョブ id）。無ければ先頭。`''` はジョブ無し。保存は #738、メニューは #880。エンジンは入力を受けるだけ（装備の `roster.equipment` と同じ流儀） |
| 検査 | 宣言が無い・就けるジョブに入っていない → 警告してジョブ無し（戦闘は続く） |
| 能力値 | `resolveMemberEquipment` の合計（魔石＋装備品＋成長）にジョブの `装備時` を足す |
| 属性 | 耐性の層の**最後**に積む（魔石 → 装備品 → ジョブ、合計 2 層まで。超えたらジョブの層が先に落ちる。装備は作者が選んだ構成なので、常時のパッシブより優先する）。攻撃の属性にはならない |
| 転職の計算 | 純関数 `changeJob`。いつ転職できるか・費用は作品側（sit は「いつでも」「壮年編までは戦闘中不可」「仲間は本人のイベントでのみ」と記録が揺れているので、エンジンは決めない） |
| 持たないもの | わざ・コマンド・`装備可`（ジョブによる装備種別の制限）。sit は刀の装備可を #207 の `装備可` で表せ、ジョブは固有コマンドを持たないため必要としない。必要になったら段階 2 で足す |
| 検証 | ハーネスの族 `job`（ジョブの組み合わせ × 敵の相性 × HP × 操作 × ターン制/ATB）。既存族は `HARNESS_SKIP=job` で従来とバイト一致 |
