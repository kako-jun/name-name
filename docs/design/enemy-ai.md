## 0. 要約

- FF5・FF6 の敵 AI は、どちらも「**条件で絞り、行動リストから選び、反応（カウンター）用に別スクリプトを持つ**」という同じ骨格でできている。
- name-name の敵は現状「通常攻撃しかしない」。`MonsterDef.builtin` は解析されるが、戦闘エンジンは読んでいない（呪文・アイテムの builtin だけ配線済み）。確率・条件・カウンターはどれも表現できない。
- 設計案は、`[モンスター]` ブロックに **`行動:` と `反撃:` の行**を足す。書かない敵は今と同じ挙動のまま。状態は「敵ごとの行動回数」などの**進行カウンターだけ**を `BattleState` に持つ（ATB ゲージと同じ位置づけ）。
- 段階案: P0 特技の土台 → P1 行動・重み・条件 → P2 順番・予兆 → P3 カウンター・死亡時（P4 形態変化・連携・変数は後日）。

### 1.2 FF6 の仕組み [A]

敵 1 体につきスクリプトが **2 本**ある。

1. **ターンスクリプト**: その敵の行動番ごとに実行する。
2. **カウンタースクリプト**: その敵が攻撃を受けたとき（カウンターの機会ごと）に実行する。

スクリプトは命令の並びで、`FC 条件 …` から `FE` までが「条件が真のときだけ実行されるブロック」。`FD` は「次の自分の番まで待つ」。`FF` で終わり。

| 種類 | 命令・条件 | 内容 |
|---|---|---|
| 単発行動 | 00〜EF | その番号の技を使う |
| 確率つき抽選 | `F0 s1 s2 s3` | **3 択から 1 つをランダムに実行**（重みは均等。偏らせたいときは同じ技を重ねて書くのが定石） |
| ターゲット変更 | `F1 target` | 次の技の対象を指定（個別キャラ、全体、ランダム、最後に攻撃した者、自分、仲間のランダム等。コード 00〜4D） |
| 形態変化 | `F2` | 編成を切り替える（新しい敵の HP を満タンにするフラグあり） |
| メッセージ | `F3` | メッセージ表示 |
| 敵の出し入れ | `F5` | 敵の表示/非表示を切り替える（HP 保持・満タンの区別あり） |
| アイテム使用 | `F6` | 2 つのうちランダムでアイテムを使う |
| イベント | `F7` | 特殊イベント起動 |
| 変数 | `F8` `F9` | 数値変数の設定・加減算、ビットの設定/解除/反転 |
| アニメ | `FA` | 敵の前進・後退・点滅・サウンド等 |
| その他 | `FB` | 無敵化/解除、ターゲット不可、戦闘終了、永続ステータスの付与/解除、**戦闘タイマーのリセット** |
| 条件: 被弾の種類 | `FC 01`〜`04` | コマンド ID / 呪文 ID / アイテム ID / **属性ビット**で受けた |
| 条件: HP が減った | `FC 05` | 自分の HP が減った |
| 条件: HP・MP | `FC 06` `07` | 対象の HP が（値×128）未満 / MP が値未満 |
| 条件: 状態異常 | `FC 08` `09` | 対象が状態を持つ/持たない |
| 条件: タイマー | `FC 0B` `16` | 戦闘タイマー / グローバルタイマーが値より大きい |
| 条件: 変数 | `FC 0C` `0D` `14` `15` | 変数が値より小さい/以上、ビットが立つ/立たない |
| 条件: レベル | `FC 0E` `0F` | 対象のレベルが値未満/以上 |
| 条件: 仲間・単独 | `FC 10` `11` `12` `13` | 生きている敵が 1 種類だけ / 指定の敵が生存 / 死亡 / キャラまたは敵の数が値以下 |
| 条件: 弱点・編成 | `FC 1A` `1B` | 対象が指定属性に弱い / 現在の編成が指定のもの |
| 恒真・恒偽 | `FC 1C` `0A` | 常に実行 / 実行しない |

要点:
- **条件は被弾側から見える情報（属性・コマンド・呪文・アイテム）にも、状態（HP、仲間、タイマー、変数）にも掛けられる**。
- 状態の記憶は**数値変数とビットフラグ**（`F8` `F9` / `FC 0C` 等）と**戦闘タイマー**。「N 回目で変化」「ターンごとに前進する」はこの変数で作られている。
- 対象指定が独立した命令（`F1`）なので、「同じ技を、時には弱い相手に」などが作れる。

### 1.3 FF5 の仕組み [B]

`MonsterATB`（敵の ATB が満タンになったときの処理）を読んだ範囲での構造:

- 敵 1 体のデータに **最大 10 個の「条件セット」**があり、各セットは **最大 4 個の条件**（AND）と、**そのセット専用の行動スクリプト**を持つ。
- 番が来ると、**セット 0 から順に、全条件を満たす最初のセット**を選び、そのスクリプトを実行する（条件が空/恒真のセットは常に成立）。つまり「上から順に評価し、最初に当たったものを採用」。
- 実行するスクリプトの**進行位置は敵ごとに記憶**され、次の番はその続きから実行する。スクリプトの終端（`FE` / `FF`）に来ると先頭に戻る。→「1 ターン目は A、2 ターン目は B、3 ターン目は C、また A…」の**順番どおりの行動**が作れる。条件セットが切り替わると位置は新セットの先頭にリセットされる。
- スクリプトの 1 要素は、**技 1 つ**、または**技 3 つのうちランダムに 1 つ**（`AIChoose1of3`: 命令番号が F0 未満なら 3 択のリスト）、または特殊命令（`FD` の後ろ）。
- 特殊命令（確認できたもの）: 形態/表示（`F2` 敵を出す）、対象指定（`F3`）、変数設定（`F4`、変数は 0〜3 の 4 個）、イベントフラグ設定（`F9`）、ステータス/能力値の設定・状態の切替（`FA`）。
- 条件（`CheckAICondition`、0x00〜0x12）:

| 番号 | 内容 |
|---|---|
| 00 | 常に成立 |
| 01 | 対象の状態異常を確認 |
| 02 | 対象の HP が値未満（絶対値） |
| 03 | 変数（0〜3）が値と等しい |
| 04 | 単独である / 生きている敵がすべて同種である |
| 05 | 見えている敵の組み合わせが指定と一致/不一致 |
| 06 | **被弾への反応: コマンドと属性** |
| 07 | **被弾への反応: コマンドとカテゴリ** |
| 08 | 被弾への反応: 魔法 |
| 09 | 被弾への反応: アイテム |
| 0A | 被弾への反応: 対象の取られ方 |
| 0B | キャラクタの能力値パラメータの確認 |
| 0D | イベントフラグの確認 |
| 0E | 被弾への反応: ダメージを受けた |
| 0F | 死亡している場合の判定を有効にする（恒真。死亡時の行動を許すためのスイッチ） |
| 10 | パーティで生存者が 1 人 |
| 11 | 被弾への反応: 召喚 |
| 12 | 女性の対象がいない |

- **反応（カウンター）**は同じ条件セットの仕組みを使う別のスクリプト実行（`Runs a Reaction AI Script`）。条件 06〜0A, 0E, 11 が反応用で、「反転」パラメータ（一致したら不成立）を持つ。
- 魅了/操作された敵は、通常の AI の代わりに ROM の「操作用行動テーブル」（敵ごとに 4 つ）から選ぶ。これは AI が行動候補のテーブルを持つ例。
- 伝聞 [D]: FF5 の Enemy ページの要約は「AI は、ATB 満タン時の行動（行動しない・2 回行動を含む）と、特定の行動を受けたときのカウンター行動を決める」と述べる。[B] の構造と一致する。

### 1.4 FF5 と FF6 の違い（設計上の含意）

| | FF5 [B] | FF6 [A] |
|---|---|---|
| 構造 | 条件セット（上から順に評価、最初に成立したものを採用）＋セットごとの順番スクリプト | 1 本の命令列。`FC … FE` の入れ子ブロックで条件分岐 |
| 状態の記憶 | 進行位置（敵ごと）、変数 0〜3、イベントフラグ | 変数、ビット、戦闘タイマー |
| ランダム | 3 択 | 3 択（`F0`）。重みは同技の重複で表現 |
| カウンター | 条件セットを共有する別の「反応スクリプト」 | 「カウンタースクリプト」（ターンスクリプトと同形式） |

name-name の設定として書きやすいのは、**FF5 の「上から順に評価、最初に成立したものを採用」**＋**FF6 の条件の豊富さ**。

## 2. 現状分析: name-name の敵の行動モデル

読んだ箇所: `frontend/src/game/battleEngine.ts`、`spellDsl.ts`、`builtin.ts`、`parser/src/models.rs`（`MonsterDef`）、`docs/spec/markdown-v0.1.md`（モンスター・呪文・効果 DSL）、`docs/architecture.md`、`docs/adr/0002-deterministic-state-and-debuggability.md`。

### 2.1 いま何をするか

- 敵（`BattleEntity`）は `hp, mp, atk, def, agi, resist, affinity, status, buffs, exp, gold, sprite, poses, row` を持つ（`affinity` は #872、`resist` は内部の倍率で markdown からは設定できない）。
- **従来ターン制**: `runEnemyTurn` が生存している敵全員を固定順に処理し、**先頭の生存味方**を通常攻撃する。
- **ATB**: 敵のゲージが満タンになると `runAtbEnemyAction` が**生存味方からランダム 1 人**を通常攻撃する（rng 注入）。
- **ダメージ式**: DQ 式（atk - def/2 + rand(0..atk/4)）、最低 1。後衛の半減あり（#747）。
- **`MonsterDef.builtin`**: parser は保持するが、戦闘エンジンは**敵の行動に使っていない**（`rg "\.builtin"` で呪文・アイテムの `invokeBuiltin*` だけ。`EventDisplay` は表示のみ）。仕様書にも「特殊行動はここに委譲」と書かれているが未配線。
- 呪文・アイテムの効果 DSL（`heal` / `damage` / `buff` / `debuff` / `revive` / `status` / `escape_*`）は味方（プレイヤー）側の `selectSpell` / `selectItem` からしか呼ばれない。対象解決（`resolveSpellTargets`）は「施す側＝味方」前提で、`味方単体` = 味方、`敵単体` = 敵。

| 隊列（後衛） | できる | 敵にも適用 |
| ドロップ/ぬすむ | 別 Issue | #831 |

## 3. 設計案

### 3.1 設計の前提

1. **エンジンは汎用のまま**。ゲームごとの特例（ウルトロスの墨等）はゲーム側 `.md` の設定で書く。
2. **既定は不変**。`行動:` `反撃:` を一つも書かない敵は、今と同じ通常攻撃で、**rng の消費順も同じ**（既存の戦闘テスト・リプレイが壊れない）。
3. **既存の流儀に合わせる**: `[モンスター]` ブロックの `キー: 値` の行、値は「parser は生文字列で透過し、runtime が解釈する」（`効果:` DSL と同じ、不正式は warning + 無視）。敵の技は呪文ではない（kako-jun 指示）ので、専用の **`[特技 id]` ブロック**で定義する。効果の書式（`効果:` DSL / `builtin:`）は内部で既存の評価器を共有するが、設定上の語彙とブロックは `[呪文]` と別にし、味方の呪文・アビリティと混ざらない。
4. **ADR 0002**: 持ち越す状態は「ゲーム進行そのもの」（ATB ゲージと同じ位置づけ）の**最小の数値カウンターだけ**。演出の中間状態は持たない。選択ロジックは純粋関数（`state` と `rng` を受けて行動を返す）にして、同じ `state` と rng 列なら必ず同じ結果にする。

### 3.2 持つ状態（`BattleState` への追加）

敵が `行動:`/`反撃:` を持つときだけ、`BattleState.enemyMemory?: EnemyMemory[]`（`enemies` と同じ index）を持つ。

```ts
interface EnemyMemory {
  acted: number                 // その敵が行動した回数（初手・N ターン目・周期の判定に使う）
  rule?: number                 // 直前に選ばれた `行動:` 行の番号（順番の巡回位置のリセット判定。P2）
  pos: number                   // その行の `順番=` 内の位置（P2。終端で 0 に戻る）
  used: Record<string, number>  // 行動 id ごとの使用回数（回数制限・順番）
  hits: number                  // 被弾回数（「N 回受けたら」）
  vars: Record<string, number>  // 任意の変数（FF5/6 の変数に相当。P4 で使う）
}
```

- 毎フレームの演出状態ではなく、行動の結果として増える整数のみ。セーブ/復元は `BattleState` ごと JSON でよい（ADR 0002 のスナップショット方式と整合）。
- 行動回数は `events`（直近 30 件の演出用ログ）からは再計算できないので、持つ。
- 持たなくてよいもの: 「現在のターン番号」。従来ターン制の全体ターン、ATB の全体時間は条件に使わず、**その敵の行動回数 `acted`** を使う（ATB と従来ターン制で意味が揃う）。

### 3.3 書き方（案）

`[モンスター]` に次のキーを足す。キーは複数行書ける（書いた順に、上から評価）。

| キー | 別名 | 内容 |
|---|---|---|
| `行動` | `action` | 行動ルール 1 行。`条件` を満たす最初のルールを採用し、その候補から抽選 |
| `反撃` | `counter` | 被弾後に差し込む行動ルール（P3） |
| `死亡時` | `onDeath` | 倒されたときに 1 度だけ行う行動（P3） |

ルール 1 行の書式（スペース区切りの `キー=値`。候補は `|` で区切り、`:` の後ろが重み）:

```
行動: 条件=<式> 候補=<技>[:<重み>] | <技>[:<重み>] ... [対象=<指定>] [予兆=<文言>] [上限=<N>]
```

- `候補` の技名は `こうげき`（通常攻撃）または `[特技 id]` の id。重みを省くと 1。
- `条件` は `,` 区切りの AND。式は下表。**書かない/`常に`** なら常に成立。
- **評価順は FF5 型**: 上から順に調べ、最初に条件が成立した行を採用。成立する行が無ければ通常攻撃（= 既定）。
- **順番どおり**は `順番=A > B > C`。FF5 [B] と同じく、敵ごとに「選ばれている行」と「その行の中の位置」を記憶し、実行するたびに位置を進め、終端で先頭に戻る。選ばれる行が切り替わったら位置は新しい行の先頭にリセットする（[B] で確認。FF5 は条件セットが変わると位置を新セットの先頭に戻す）。

条件の式（語彙の案。P1 で最小、後の段階で足す）:

| 式 | 意味 | 元の仕組み | 段階 |
|---|---|---|---|
| `初手` | その敵の最初の行動（`acted == 0`） | FF6 タイマー0 | P1 |
| `HP<50%` / `HP>=50%` | 自分の HP 割合 | FF6 `FC 06` | P1 |
| `仲間=0` / `仲間<=1` | 自分以外の生存している敵の数 | FF6 `FC 10` `13`、FF5 04 | P1 |
| `味方<=1` | 生存している味方の数 | FF5 10 | P1 |
| `回数>=3` | その敵の行動回数 | FF5 進行位置 | P2 |
| `周期=3/0` | `acted % 3 == 0` | FF5 進行位置 | P2 |
| `状態=毒` `味方状態=眠り` | 自分/いずれかの味方の状態異常 | FF6 `FC 08`、FF5 01 | P2 |
| `使用<技>>=1` | その行動の使用回数（1 度きり・上限） | 変数/ビット | P2 |
| `被弾>=5` | 被弾回数 | FF6 変数 | P3 |
| `受けた=物理` `受けた=魔法` `受けた=系統:fire` `受けた=呪文:メラ` `受けた=アイテム` | 直前の被弾の種類 | FF6 `FC 01`〜`04`、FF5 06〜09 | P3 |
| `仲間が倒れた` | 他の敵が倒れたとき | FF6 `FC 12`、FF5 05 | P4 |
| `変数<名前>=N` | 敵ごとの変数 | FF5 03、FF6 `FC 0C` | P4 |

対象の指定（`対象=`、省略時は特技の `対象` に従う）: `ランダム` / `最後に攻撃した者` / `HP最小` / `全体` / `仲間` / `自分`。

**特技の `対象:` は「使う側から見た相対表現」にする**（案）。`相手単体` / `相手全体` / `自分` / `仲間単体` / `仲間全体`。敵が使えば「相手」はプレイヤー側、将来プレイヤー側が使えば敵側、と同じ語彙で読める。`[呪文]` の `敵単体`/`味方全体` は「味方起点」前提の絶対表現なので、特技では使わない（読み替えが不要になる）。

**`[特技 id]` のキー（案）**: `名前`（敵固有の表示名）/ `対象`（上記の相対表現。既定 `相手単体`）/ `効果`（既存の効果 DSL と同書式。`builtin` と排他）/ `builtin` / `メッセージ`（使用時に出す演出文。例: `{user}は 墨を はいた！`）/ `予兆`（P2）。**MP は持たない**（消費しない。回数制限は `上限=` と `使用` 条件で表す）。

**id 規約**: sit-by-me では特技の id にも `sit_` 接頭辞＋英語3語の規約が適用され、DQ・FF 固有名を id に混ぜない（例: `sit_ink_spray_all`）。以下の擬似設定は読みやすさのため短い id にしている。

### 3.5 エンジン側の入れ口

- 追加する関数: `chooseEnemyAction(state, enemyIndex, rng): ChosenAction`（純粋。state の変更は `acted++` 等だけ別関数で行う）。`runEnemyTurn` と `runAtbEnemyAction` の「通常攻撃する」部分をこの関数の結果に差し替える。行動を書かない敵は `{ kind: 'attack' }` を返し、**rng を余分に消費しない**。
- 特技の実行は既存の `applyEffect`（効果 DSL の評価器）と builtin 呼び出しを内部で再利用し、`caster` を使う側として呼ぶ。演出イベント（`BattleActionEvent`、#745）は `kind` に `'skill'` を足して記録する（FF 式演出は `label` に特技名を出す。呪文と同じ表示経路を通すが、語彙は別）。特技は MP を消費しない。
- カウンター（P3）は、プレイヤー/敵の行動の解決後に「被弾した敵」を見て `反撃` を評価する。**再帰を避ける**ため、反撃からの反撃は行わない（1 段まで）。複数ヒットでの多重反撃や、反撃で倒れた場合の処理も P3 で定義する。
- parser: `MonsterDef` に `actions: Vec<String>`（生文字列）、`counters: Vec<String>`、`on_death: Option<String>` を足す。効果 DSL と同じく parser は透過し、`frontend/src/game/enemyAi.ts`（新規）で解釈する。不正な行は warning + 無視（既定へフォールバック）。
- docs: 仕様書のモンスター表と architecture.md に追従。ユーザー向けに sit-by-me のような作品側へは、台帳に行動表を足せる。

### 3.6 論点の確定事項

kako-jun 指示（2026-10-14）「解析結果にまかせる」に基づき、FF5・FF6 の ROM 解析で確認できた点はそれに従い、確認できない点は最小の安全側の既定を置いた。

1. **確定（kako-jun）**: 敵の技は専用の `[特技]` ブロック。呪文とは別の語彙・ブロックで、効果 DSL の評価器だけ内部共有。
2. **特技の対象表現**: 使う側から見た相対表現（`相手単体` / `相手全体` / `自分` / `仲間単体` / `仲間全体`）。§3.3 のとおり。
3. **特技は MP を持たない**（回数制限は `上限`）。FF の敵の技は MP 消費を前提にした作りが [A][B] の範囲では確認できなかったため（資料で未確認なので、持たない側に倒した）。
4. **ATB と従来ターン制の揃え方（確定）**: 行動の選択は、どちらの方式でも**その敵の行動回数 `acted` と記憶（行・位置）**だけで決める。FF5 は進行位置を敵ごとに記憶し（`AICurrentOffset`）、FF6 は敵ごとの変数とタイマーで状態を持つ [A][B]。どちらも「全体のターン番号」ではなく**敵ごとの記憶**で動くので、同じ形にする。従来ターン制の全体ターン、ATB の全体時間は条件に使わない。
5. **カウンターの扱い（確定）**:
   - **別の台本にする**: FF6 はターンスクリプトとカウンタースクリプトの2本を持つ [A]。FF5 も反応用のエントリを別に持ち、条件セットを共有して選ぶ [B]。→ `反撃:` は `行動:` とは別の行として書く。
   - **1 トリガー 1 行動・位置を持たない**: FF5 の反応処理（`ProcessReaction`）は、選ばれた反応エントリの先頭から 1 つ分の行動だけを組み立てて実行し、ターン行動のような進行位置の更新は行わない [B]。→ `反撃:` の候補は毎回、先頭から抽選する（`順番=` は反撃では使えない）。
   - **被弾した敵ごとに評価する**: FF5 は攻撃の結果ごとに、被弾した各モンスターの反応を確認する（`Check for and launch any reactions to the attacks this tick`）。→ 全体攻撃では被弾した敵それぞれが 1 回ずつ反撃しうる。
   - **死亡時**: FF5 には「死亡している場合も判定する」条件（0F）が別にある [B]。通常は倒れた敵は行動しない。→ `死亡時:` は専用の行として、倒れた時に 1 度だけ実行する。
   - **資料で未確認の点（最小の安全側の既定）**: 反撃が更に反撃を起こすか（FF5 は反撃中を示すフラグ `CurrentlyReacting` を持つが、連鎖の扱いは確認できていない）→ **連鎖は 1 段**（反撃は反撃を起こさない）。1 回の行動で同じ敵に複数ヒットしたときの反撃回数 → **1 行動につき 1 回**。FF5 は 2 回目の攻撃用の第2反応スロットを持つが、複数ヒットとの関係は確認できていない。
6. **段階の順序（確定）**: P0（特技の土台）→ P1（行動・重み・条件）→ P2（予兆・順番）→ P3（カウンター・死亡時）。sit-by-me の予兆・順番を、カウンターより先に使えるようにする。各段階を 1 PR にする。実装 Issue は §3.8。

### 3.7 sit-by-me の台帳との関係

`docs/monsters.md` は属性・弱点・役割・ドロップ/ぬすむ（別表）を管理し、方針として「通常敵・中ボスは、弱点を突く一解にせず、複数の勝ち筋と観察できる予兆を持たせる」としている。この設計はその受け皿になる。

- 予兆 → `予兆=` と `順番=`
- 弱点 → `弱点:`（属性相性、#872）。弱点を突くとカウンターする敵は `弱点:` と `反撃: 条件=受けた=系統:…` を両方書く（`受けた=弱点` は未実装）
- 複数の勝ち筋 → 同じ敵に `HP<50%` や `仲間<=0` で別の行動を持たせ、状況ごとに答えを変える
- 台帳には行動表（行動 id、条件、予兆）の列/別表を足せる。台帳の「記録に無いことは決めない」ルールに従い、決まるまで空欄にする。これは sit-by-me 側の運用で、この設計の前提ではない。

### 3.9 実装状況と、実装で確定・変更した点

| 段階 | 状況 | 実装 |
|---|---|---|
| P0 敵が `[特技]` を使える土台 | 実装済み | #845 |
| P1 `行動:`・重み付き抽選・基本条件 | 実装済み | #849 |
| P2 `順番=`・予兆・`上限=`・回数/周期/使用/状態条件 | 実装済み | PR #852 |
| P3 `反撃:`・`死亡時:`（被弾後のフック） | 実装済み | #837 |
| P4 形態変化・仲間への反応・変数 | 未起票 | — |

**実装 = 仕様の正本は `docs/spec/markdown-v0.1.md`（特技・敵の行動）。** 以下は、設計案（§3.3〜§3.5）から実装で確定・変更した点で、食い違いがあるときはこちらが正。

- **`対象=` の上書き規則**: `対象=ランダム` / `HP最小` / `全体` で向きを上書きするのは、特技の `対象:` が `相手単体`（省略・未知を含む）のときだけ。`仲間単体` / `仲間全体` / `自分` / `相手全体` の特技は、これらを書いても向きが変わらない（`相手全体` の墨に `対象=HP最小` を付けても全員に当たる。`仲間単体` の回復に付けても敵がプレイヤーを回復しない）。`対象=仲間` と `対象=自分` は、どの特技の向きも常に上書きする。`ランダム` / `HP最小` は通常攻撃にも効く。
- **倒れた対象**: 倒れている者を対象にできるのは、蘇生の特技（`効果: revive` または builtin `zaorik`）の `仲間単体` だけ。蘇生でない特技が倒れた者を指しても最初の生存者に落ちる（死者は回復で生き返らず、「たおれた！」も二重に出ない）。
- **同時全滅**: 特技の効果で味方側・敵側が同時に全滅したとき、従来ターン制は敗北、ATB は勝利（現状の挙動をテストで固定）。
- **予兆だけの特技**: 効果も builtin も持たない特技（予兆専用）は、`hits` が空のイベントになり、効果のログを出さない（#852）。予兆の文言だけが出る。予兆は特技の `予兆:` か行の `予兆=`（行が優先）で、ログと `BattleActionEvent.omen` に載り、FF 式ではメッセージ窓に特技名の代わりに出す。
- **`順番=` と `候補=` は併用不可**: 併記した行は不正として無視する。`順番=` の要素に重みは付けられず、`順番=` の行は rng を消費しない。
- **`上限=N` は行単位**: その行を選べる回数（1 以上の整数）。使い切った行は成立しない扱いで、次の行へ落ちる（設計案の「行動 id ごとの使用回数」ではない。行動 id ごとの回数は条件 `使用<特技>>=N`）。
- **`周期=N/R`**: `acted % N == R`（R 省略は 0。N は 1 以上、R は N 未満）。`周期=3` は 1・4・7 回目の行動で成立する。
- **状態条件の制限**: `状態=` / `味方状態=` は既存の `BattleEntity.status`（効果 DSL の `status` が書く印）を見るだけ。エンジンはターン経過で残りターンを減らさず、状態異常による行動不能もまだ無いので、「効果で付いた印があるか」の判定にとどまる。
- **記憶の持ち方**: `enemyMemory[i]` は `行動:` を持つ敵がいる戦闘だけ作り、`順番=` `上限=` `使用<>` を使う敵だけが `rule` `pos` `used` `ruleUses` を行動後に持つ。それ以外の敵の記憶は `{ acted }` のまま。
- **P3 (#837)**: `反撃:` `死亡時:`、条件 `被弾>=N` `受けた=…`、対象 `最後に攻撃した者` を実装（正本は spec の「敵の反撃・死亡時」）。`仲間が倒れた` は P4 のまま未実装で、使った行は不正として無視される。実装で確定した点: 反撃・死亡時では `順番=` `上限=` は不正（進行位置を持たない）／成立する行が無ければ何もしない（`行動:` と違い通常攻撃に落ちない）／反撃は味方（プレイヤー側）の行動で被弾した敵だけが起こし、敵が敵に当てた行動では起きない／反撃・死亡時の行動は `acted` を進めない／被弾の語彙は `行動:` でも使え、被弾の記憶（`hits` `lastHit` `lastAttacker`）は反撃・死亡時を持つ敵か被弾の語彙を書いた敵だけが持つ／`死亡時:` は原因を問わず倒れた敵が 1 度だけ使い（`died`）、連鎖で倒れた別の敵の分も続け、味方全滅後は実行しない／勝敗は反撃・死亡時のあとに 1 度だけ判定（ターン制は同時全滅で敗北、ATB は勝利）。

### 3.10 sit-by-me の台帳への行動表の書き方（例）

#836 の指示。**以下はすべて「書き方の例」であり、sit-by-me で決まった行動ではない。** sit-by-me の `docs/monsters.md` に行動は一つも記録されていない（「記録に書いていないことは決めない」）。例の元にしたのは、台帳にある次の事実だけ。

- M001 段ボールのドラゴン: 幼稚園編・冒頭のお遊戯会の劇の戦闘相手。ボスか雑魚かは未定。HP120 は戦闘サンプルの試作値で本番値ではない。
- M101 ロードローラー: 雪国の道路に出る機械。属性・弱点・役割は未定。
- M131 スズメバチ: 生物。出る場所・属性・役割は未定（絵だけ採用済み）。
- 方針（`docs/systems.md` §、台帳 §2）: 通常敵・中ボスは観察できる予兆を持たせ、弱点を一つ突くだけの一解にせず、複数の勝ち筋を置く。
- id 規約（`docs/systems.md`）: 呪文・アビリティ・アイテムは `sit_` 接頭辞＋効果を表す英単語 2〜3 語（小文字スネークケース）。DQ/FF の固有名は id に使わない。**この規約は `[特技]` の id にも適用する。**

台帳には、既存の表と別に「行動表」を足す。敵ごとに 1 行、行動の列は **行動ルール（`行動:` の文字列そのまま）・使う特技 id・予兆・答え（複数）** とする。決まっていない欄は「未定」と書く。

| ID | 名前 | 行動ルール（`行動:`） | 使う特技 id | 予兆 | 答え（複数。systems.md の方針） | 根拠 |
|---|---|---|---|---|---|---|
| M001 | 段ボールのドラゴン | **例**: `順番=sit_roar_warning > sit_cardboard_smash` | **例**: `sit_roar_warning`（効果なし・予兆だけ）、`sit_cardboard_smash`（相手全体への物理ダメージ） | **例**: 「段ボールの口が ぱかっと ひらいた！」 | 未定 | 例（行動は未決。台帳は M001 の役割も未定） |
| M101 | ロードローラー | **例**: `順番=sit_engine_rev > sit_road_crush > こうげき` | **例**: `sit_engine_rev`（予兆だけ）、`sit_road_crush` | **例**: 「ロードローラーが ゴゴゴと うなっている！」 | 未定 | 例（行動は未決） |
| M131 | スズメバチ | **例**: `条件=仲間<=0 候補=sit_sting_poison` ＋ `候補=こうげき:2 \| sit_sting_poison:1` | **例**: `sit_sting_poison`（毒の付与） | **例**: 単独になると羽音が高くなる、など | 未定 | 例（行動は未決。群れで出るかも未定） |

これを `[モンスター]` / `[特技]` に起こすと次の形になる（すべて例）。

```markdown
[特技 sit_roar_warning]
名前: ほえるそぶり
対象: 自分
予兆: 段ボールの口が ぱかっと ひらいた！
[/特技]

[特技 sit_cardboard_smash]
名前: だんぼーるアタック
対象: 相手全体
効果: damage 8..12
メッセージ: {user}は 紙の しっぽを ふりまわした！
[/特技]

[モンスター example_cardboard_dragon]
名前: 段ボールのドラゴン
HP: 120
ATK: 8
DEF: 2
AGI: 3
行動: 順番=sit_roar_warning > sit_cardboard_smash
[/モンスター]

[特技 sit_sting_poison]
名前: どくばり
対象: 相手単体
効果: status poison duration=3
[/特技]

[モンスター example_hornet]
名前: スズメバチ
HP: 20
ATK: 6
DEF: 1
AGI: 9
行動: 条件=仲間<=0 候補=sit_sting_poison
行動: 候補=こうげき:2 | sit_sting_poison:1
[/モンスター]
```

予兆（`sit_roar_warning`）は効果を持たない特技なので、1 ターン目は何も起きず文言だけが出る。2 ターン目に大技が来る。「答え」の欄に書く複数の勝ち筋（防御する・ATB の順番で先に動く・退避する等）は、sit-by-me 側で決まってから台帳に足す。上の `example_` 付きの敵 id は説明用で、sit-by-me の敵 id の規約ではない（台帳は敵に `M` + 通し番号を使う）。
