# 操作ガイド

Name×Name の操作方法（ノベルプレイヤー + RPG プレイヤー）。
エディタ画面の使い方は [エディタガイド](./editor.md) を参照。
特定シーン・状態を URL／コードで再現する開発者向けの手順は [デバッグガイド](./debugger.md) を参照。

## TUI版スプラッシュ

TUI版は `tui-config.toml` の `[splash]` で起動画面を設定できます。

- `splash.logo_image`: `event_image.assets_dir` を基準にしたロゴ画像の相対パス。設定すると、画像をキャンバス全幅に contain 表示し、画面に収まらない縦方向は ↑ / ↓ でスクロールします。
- `splash.scroll_ease_ms`: ↑ / ↓ のスクロールアニメーション時間（ミリ秒）。`0` にすると即時移動します。
- ↑ / ↓: 画像ロゴを1行ずつ上下にスクロールします。最上端・最下端を越えて移動することはありません。
- `logo_image` が正常に読み込めた場合は `splash.lines` は無視されます。
- `logo_image` の読み込みに失敗した場合は `splash.lines` のテキスト表示へフォールバックします。`lines` が空でも、空行と画面最下部の共通操作フッター（下記）は表示されます。
- 画面最下部には、起動直後のスプラッシュ画面から通常プレイまで常時、操作キー一覧のフッターを表示します（#587）。旧仕様の起動時「Enter / Space で開始」単独表示は廃止し、`Enter/Space 次へ / ↑/↓ 選択 / A オート / S スキップ / B バックログ / C 設定 / Q/Esc 終了` を同格で常時提示します。これにより初見でも設定 (`C`) やバックログ (`B`) の存在を確認できます。ただし「常時」は固定キャンバス（130 列 x 33 行）以上の端末に限る — それ未満の端末では（ロゴ画像モード・テキストモードいずれも）フッターを含む通常のゲームUI自体を描画せず、「端末を広げてください」という案内メッセージにフォールバックします（TUI版はGUI版のような動的リサイズを行わない設計判断のため。セルフレビューで発覚: 修正前はテキストモードだけこのガードが欠けており、狭い端末でフッターの一部だけが欠落表示されていた、#587）。

## TUI版セーブ（#579）

TUI版はGUI版のような複数スロットのメニュー式セーブ/ロードは持たず、**自動クイックセーブ/自動クイックロードのみ**を持つ。

- シーンが切り替わるたびに、現在のフラグ・シーンID・既読行を自動でファイルに保存する（選択肢の有無に関係なく毎シーン）
- BGM・イベント絵・暗転状態など、着地シーンより手前で宣言され着地シーン自身では再宣言されず前のシーンから引き継いでいるだけの状態も、保存時点の値としてあわせて保存・復元する
- 起動時に保存ファイルがあれば自動で読み込み、前回の続きから再開する
- 保存先は `--config` で指定したconfigファイルと同じディレクトリ（`--config`未指定時はカレントディレクトリ）
- 保存済みのシーンIDが原稿変更等で見つからない場合は、フラグ・シーン位置・既読行のいずれも復元せず、通常の初期状態から開始する（部分的な復元による不整合を避けるため）
- 書き込みに失敗した場合も進行は止まらない（サイレントに継続）
- 保存ファイル名は `.name-name-tui-quicksave.json` 固定。エンジン本体のリポジトリの `.gitignore` には登録済みだが、保存先はゲームプロジェクト（原稿）側のリポジトリ内になることが多いため、開発者は自分のゲームリポジトリの `.gitignore` にもこのファイル名を追加し、個人のプレイ状態を誤ってコミットしないようにすることを推奨する
- `--new-game`（#622）: 起動時にこのフラグを付けると、既存のクイックセーブファイルの有無に関わらず必ず原稿の先頭（entry_scriptの最初のシーン）から開始する。フラグが立っている場合、既存のクイックセーブファイルは削除してから起動する（以後は通常起動でも今回の新規開始が自然に「続きから」として引き継がれる）。ファイルが存在しない場合はエラーにならない。**削除に失敗した場合（権限エラー等）は、他の自動セーブ処理と異なりfail-softにせずエラーとして起動を中断する**（新規開始の要求を黙って無視しないため）

## ノベルプレイヤー

### キーボードショートカット

| キー | 動作 |
|---|---|
| Space | 次のテキストへ |
| Enter | 次のテキストへ |
| → (右矢印) | 次のテキストへ |
| ← (左矢印) | 前のテキストへ |
| S | セーブメニューを開く |
| L | ロードメニューを開く |
| B | バックログの表示/非表示を切り替え |
| Escape | 開いているオーバーレイを閉じる |

### マウス・タッチ操作

| 操作 | 動作 |
|---|---|
| クリック / タップ | 次のテキストへ |
| 黒帯（letterbox/pillarbox の余白部分）をクリック / タップ | 次のテキストへ（canvas の外側でも同じ動作。canvas 自身のクリック判定が届かないため #467 で追加） |
| シークバー帯をタップ / ドラッグ | その位置にジャンプ（同時にスライダが前面に出て下部ボタンが一時退避。シーク操作はテキスト送りを兼ねない） |

### テキスト送り

ダイアログ（台詞）とナレーションはカノソ方式で表示される:
1. テキストが一瞬で全文表示される
2. クリック / Space / Enter / → で次のテキストに進む
3. ← で前のテキストに戻る

背景変更・BGM再生・暗転などの演出イベントはユーザー操作なしで自動実行される。

作品の frontmatter `dialog_style: "novel"`（全画面ノベル）では送りが**文単位（息継ぎ単位）**になる (#292)。クリック / タップは句点・感嘆符・疑問符で割った文を 1 つずつ送り、既出の文は同じページに溜まる。文末の右に出るクリッカーは種別で形が違う: `▼` は同じページに次の文がある（続き送り）、`❯` はそのページの最後の文＝次のクリックで改頁。ページが尽きたら次のテキストへ進む。

さらに、脚本の本文中に書かれた**単独行 `---`** は手動の強制改頁になる (#292 Phase 2)。自動改頁（収まる行数で区切る）より早くページを切りたいときに作者が入れる印で、`---` を境に続きの文が新しいページの先頭から始まる。`---` を含まない脚本は文単位送りの挙動そのまま（変化なし）。

`dialog_style: "adv"`（既定・下部 ADV 箱）は従来どおり 1 クリックで次のテキストに進む（`---` の手動改頁・文単位送り・クリッカー 2 種は novel 専用）。

### セーブ/ロード

#### セーブ

1. **S** キーを押す（またはセーブボタンをクリック）
2. セーブメニューが表示される（3スロット）
3. 保存したいスロットをクリック
4. 現在の状態がスロットに保存される

#### ロード

1. **L** キーを押す（またはロードボタンをクリック）
2. ロードメニューが表示される
3. 読み込みたいスロットをクリック
4. 保存時の状態が復元される（背景・BGM・立ち絵・テキスト位置）

#### データのエクスポート/インポート

セーブデータを JSON ファイルとしてエクスポート・インポートできる。別のブラウザや端末にデータを移行する場合に使用。

#### クイックセーブ/クイックロード

**F5** キーで現在の状態をクイックセーブ（3スロットとは独立した専用スロット）、**F8** キーでクイックロードする（#142）。

#### 自動クイックセーブ/自動クイックロード（#578）

プレイヤー画面では、シーンが切り替わるたびに自動でクイックセーブする（選択肢の有無に関係なく毎シーン）。次回そのプロジェクトを開いたとき、クイックセーブデータがあれば自動で読み込んで前回の続きから再開する（`?scene=` 等の明示的な起点指定や、fluid 再マウント時の引き継ぎがある場合はそちらが優先される）。手動の F5/F8 クイックセーブと同じ専用スロットを共有する。エディタのプレビュー画面（プロジェクト未確定）では動作しない。

### バックログ

1. **B** キーを押す
2. これまでに表示されたダイアログ・ナレーションの一覧が表示される
3. **↑** / **↓** キーまたはマウスホイールでスクロール
4. もう一度 **B** を押すか **Escape** で閉じる

### シークバー（シナリオスライダ）

ゲーム全体の進行位置を確認・操作できる水平スライダ。下部の丸ボタン（S/A/⚙/D）の**中央を貫く高さ**に置かれ、通常時は控えめに表示されてボタンより背面に見える（ボタンの円を貫くライン）。

- バーの塗りつぶし部分が現在位置を示す
- フィル／つまみの色は既定で水色（`#a8dadc`）。frontmatter `seekbar_color: "#rrggbb"`（#440）で作品ごとに変えられる（例: theo-hayami の金 `#b8934f`）。トラック背景（暗いグレー）は据え置き
- スライダをタップ / ドラッグして操作すると、スライダが**前面に出て主役になる**: つまみが拡大し、影が付き、重なっている下部丸ボタンは opacity でフェード退避してスライダ操作を邪魔しない（マウスを近づけただけでは前面化しない。実際に操作した時だけ）
- バーの任意の位置で操作すると、その位置にジャンプする（背景・BGM・立ち絵などの状態も自動的に復元される）。シーク操作は「次のテキストへ」を兼ねない（同じタップで 1 つ進んでしまわない）
- しばらく操作がないか、ほかを操作すると、スライダは控えめな表示に戻り、丸ボタンが再表示される
- 暗転（[暗転] / blackout）中はスライダを表示しない（黒画面の上に薄い線が残らないようにするため）
- 動画書き出し中はスライダを表示しない（録画に焼き込まれないようにするため）

### 選択肢

選択肢が表示されたら:
1. 選択肢のボタンが画面に表示される
2. クリック / タップで選択
3. 選択に応じてフラグが設定され、対応するシーンにジャンプする

選択肢が多くて画面に収まりきらない場合だけ、選択肢一覧は画面内でスクロールできる表示になる。マウスホイールまたはタッチドラッグで上下に動かし、すべての選択肢を確認して選べる。少数の選択肢は従来どおり中央寄せで表示される。

脚本側の設定によっては、一部の選択肢が「ロック」されて表示されることがある（#591）。ロック中の選択肢は暗めの配色で見分けがつき、クリック/タップしても選択できない。特定のフラグが立つ（他のルートをクリアする等）と自動的にロックが解除される。

同様に、既にクリアしたルートに対応する選択肢は「完了」扱いの見た目（ロックとは別の暗めの配色）になることがある（#594）。ロックと違いクリック/タップで通常どおり選択でき、見た目だけがそのルートをクリア済みであることを示す。プロジェクトが任意アセット `assets/images/read-icon.webp` を用意していれば、完了扱いの選択肢はテキストの上にそのアイコンも表示する（未配置/取得失敗時は配色のみ）。まだ選んでいない選択肢についても、プロジェクトが任意アセット `assets/images/unread-icon.webp` を用意していれば同様にアイコンを表示する（ロックとは別軸の状態で、一度選んだ後かどうかは問わない、#598 追記3）。ロック中の選択肢もこの2種のアイコンの対象になり、配色だけがロック専用になる——ロックは「読むことすらできない」状態を表すだけで、未読/既読の状態自体には影響しない（#604）。

`[選択]` を持たないまま脚本の記述が尽きた場合は、選択肢経由の終劇と同じ処理が流れて画面中央に "to be continued..." が表示され、BGM 停止・背景/立ち絵フェードとともに物語が終わる（従来は無反応で固まっていた、#470）。

### オーバーレイの閉じ方

セーブメニュー・ロードメニュー・バックログなどのオーバーレイは **Escape** キーで閉じられる。

### フルスクリーン表示

画面右上隅（右下の ⚙/A/S/D ボタン列とは別位置）にフルスクリーン切り替えボタンがある (#468)。押すとゲーム画面全体（letterbox 込み。ヘッダ等は含まない）がブラウザのフルスクリーン表示になり、もう一度押すか **Escape** で解除される。見た目はせおはやみ (theo-hayami) のトグルボタンと同じデザインで、右上隅の小さな金色の三角（44x44 のタップ領域の隅に 20x20 で表示）。通常時は薄く、hover/タップ直後は濃くなる（タップ後 2.8 秒だけ濃さを保つ余韻あり）。三角の向きで通常表示中/フルスクリーン中を示す。非対応ブラウザや拒否された場合は何も起きず通常表示のまま。

### デバッグ HUD（D ボタン）

デバッグが有効な作品（frontmatter `debug_enabled`）とエディタでは、右下ボタン列に **D** ボタンが出る。押すとデバッグ HUD パネルが展開し、再押しで畳む。パネル右上の **×** ボタンでも閉じられる（全体化＝フルスクリーン中に D ボタンが HUD の裏に回っても、パネル内から確実に閉じられる）。

## RPG プレイヤー

PixiJS ベースのタイルマップ RPG モード。`gameData` を渡さない場合はサンプルデータが読み込まれてそのまま動作する。

レンダラーはシーン側の `[view=...]` 指定に応じて切り替わる:
- `[view=topdown]`（デフォルト）: 見下ろし型（TopDownRenderer）
- `[view=raycast]`: 一人称レイキャスト型（RaycastRenderer）

### 見下ろし型（TopDown）のキーボード操作

| キー | 動作 |
|---|---|
| ↑ / W | 上に 1 マス移動 |
| ↓ / S | 下に 1 マス移動 |
| ← / A | 左に 1 マス移動 |
| → / D | 右に 1 マス移動 |
| Enter / Space | 正面の NPC に話しかける / 会話ウィンドウを閉じる |

### レイキャスト型（Raycast）のキーボード操作

一人称視点。連続移動＋回転でファーストパーソン・ダンジョン探索感覚。

| キー | 動作 |
|---|---|
| ↑ / W | 前進 |
| ↓ / S | 後退 |
| ← / A | 左回転 |
| → / D | 右回転 |
| Q | 左ストレイフ（真横に移動） |
| E | 右ストレイフ（真横に移動） |
| PageUp | 上を見る（pitch +、最大 ±0.4 rad ≒ ±23°） |
| PageDown | 下を見る（pitch −） |
| Z | ジャンプ（最高約 0.375 タイル分、滞空 0.5 秒。空中での再ジャンプ不可） |
| Enter / Space | 正面タイルの NPC に話しかける / 会話ウィンドウを閉じる |

### 移動と通行判定

- **見下ろし型**: 移動はグリッド単位。1 マス移動につき約 150ms のアニメーションが入り、その間は次の入力を受け付けない
- **レイキャスト型**: 連続移動（約 3 タイル/秒、回転 約 3 rad/秒）。キーを押し続けると移動し続ける
- 木（TREE）と水（WATER）のタイル、および NPC のいるタイルには入れない（両モード共通）
- レイキャスト型では XY 分離で壁ずり衝突する（壁に斜めに当たると沿って滑る）
- マップ端を越えることもできない

### 会話

プレイヤーの向いている先のタイルに NPC がいるとき、Enter / Space で会話が開始し、画面下部にウィンドウが表示される（NPC 名と本文）。再度 Enter / Space で閉じる。会話ウィンドウ表示中は移動入力を受け付けない。両モードで同じダイアログ UI を使う。

メニューの「はなす」から会話を開始した場合、選択した tap が直後の canvas tap として canvas に届いてダイアログが即時に閉じる/進む事故を防ぐため、二段構えの防御を入れている:

1. `handleMenuSelect` の入口で `suppressNextTouchTap(DIALOG_JUST_SHOWN_GUARD_MS)` を再延長する（同一 PointerEvent シーケンス内の漏れ tap を確実に弾く一次防御）
2. `handleTap` 側で `dialogBox.isJustShown(DIALOG_JUST_SHOWN_GUARD_MS)` が真のときは close / advance / typewriter skip を全て無視する（時刻ベースの保険、suppressNextTouchTap が漏れたケース）

ガード幅は `DIALOG_JUST_SHOWN_GUARD_MS = 400 ms`（`tapMaxDuration = 350 ms` と `suppressNextTouchTap` のデフォルト 250 ms を覆える値）。EventRunner の Dialog / Narration コマンドで `dialog.show` された直後も同じガードが効く（DialogBox 側で時刻を持っているため）。

### スマホ・タッチ操作（両モード共通）(#178)

オンスクリーンの仮想パッドは出さず、ジェスチャだけで操作する:

| 操作 | 動作 |
|---|---|
| スワイプ ↑ | TopDown: 上に 1 マス移動。Raycast: 正面に 1 タイル前進 |
| スワイプ ↓ | TopDown: 下に 1 マス移動。Raycast: 1 タイル後退 |
| スワイプ ← / → | TopDown: 左右に 1 マス移動。Raycast: 90° 回転（瞬間スナップではなく約 0.16 秒のアニメーション補間。連打すると 180° / 270° と残角度が積み上がって連続回転する。残量上限は ±2π。旋回アニメ中に前進・後退すると残角度を即時 flush してから移動する。ダイアログ / メニュー表示中も補間自体は進む） |
| シングルタップ | メニューを開閉する。ダイアログ表示中はテキスト送り（typewriter スキップ → 閉じる） |
| メニュー項目を直接タップ | その項目を即実行（カーソル移動 → 決定の二段操作はしない） |
| メニュー外のタップ | メニュー表示中なら閉じる |
| メニュー表示中のスワイプ | メニューを閉じる（誤タッチ救済） |
| TopDown の連続スワイプ | 移動アニメ中の入力は最後の 1 件をキューして取りこぼさない |

メニューは **DQ4 ファミコン版相当の左上 8 コマンドウィンドウ** (#171)。普段は隠れていてタップで出る、文字を直接タップして即決定（カーソル移動なし）。
配置は FC 版 DQ4 と同じ 2 列 x 4 行:

`はなす / じゅもん`
`つよさ / どうぐ`
`そうび / さくせん`
`とびら / しらべる`

| コマンド | サブメニュー | 振る舞い |
|---|---|---|
| はなす | なし | 正面 NPC に話しかける（Enter/Space と同じ） |
| どうぐ | アイテム一覧 | (#174 で実装) |
| しらべる | なし | 足元 / 正面を調べる（#173 戦闘内 examine とは別途実装） |
| つよさ | パーティメンバー | (#175 で実装) |
| さくせん | バッチリがんばれ / いのちだいじに / じゅもんつかうな | (#173 戦闘 AI と連動) |
| じゅもん | パーティメンバー → 呪文一覧 | (#174 で実装) |
| そうび | パーティメンバー | (#175 で実装) |
| とびら | なし | 鍵付きドアを開く（#173 鍵アイテムと連動） |

サブメニューはメインの右隣に独立パネルで開く（重なり方は実装が DQ4 ファミコン版に準拠する形で後追い調整予定）。

仮想パッド・タップで歩く方式は採用しない（Issue #178 の方針）。

### ミニマップ (#149)

**Raycast モード（一人称視点）** の画面右上に **2D 全体俯瞰ミニマップ**を半透明で重ねる。一人称で迷子にならないための助け。

- マップ全体（壁 = 暗緑/青、床 = 緑/茶）を縮小表示
- プレイヤーは **赤い三角形**（向いている方向の頂点が前向き）
- NPC は NpcData の色で **小さな丸ドット**

サイズは既定 120×120 px（`max(mapW, mapH)` に合わせて 1 タイル px が決まる）。TopDown モードは元々画面全体が俯瞰図なのでミニマップは出さない（重複するため）。

**自動非表示**: ダイアログ表示中（NPC 会話）/ メニュー表示中（DQ4 8 コマンド）はミニマップを自動的に隠す。イベントシーン・戦闘中の視覚的ノイズを避けるため。探索中だけ表示される。

将来拡張: `[minimap=on|off]` のシーン属性、Per-game 既定の切替、戦闘モード（#173）への自動連動、表示/非表示切替時のフェードアニメーション。

### 戦闘プロト (#173, Phase 1)

Raycast モードで DQ4 メニューの **「しらべる」** をタップすると、テスト用の戦闘プロトが起動する（暫定経路、本来は #172 確率エンカウントで自動発火）。

レイアウト: フィールドを半透明黒で暗くした上に、敵スプライト枠（中央上部、現状はテキストのみ）+ 4 コマンドウィンドウ（たたかう / じゅもん / どうぐ / にげる）+ 戦闘ログ（最新 4 行）を重ねる。Undertale 風 + DQ1/DQ5 風（背景フィールドが透けて見える）。

| コマンド | 動作 |
|---|---|
| たたかう | DQ 式の通常攻撃。ダメージ = max(1, atk - def/2) + rand(0..atk/4) |
| じゅもん / どうぐ | Phase 1 では未実装ログのみ（パーティ #175 で本実装） |
| にげる | 50% で escaped、失敗で敵ターン |

戦闘終了（victory / defeat / escaped）で自動的に画面を畳む。経験値 / ゴールドは集計してログに出すが、レベルアップ判定は #175 まで保留。
