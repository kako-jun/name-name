# 操作ガイド

Name×Name の操作方法（ノベルプレイヤー + RPG プレイヤー）。
エディタ画面の使い方は [エディタガイド](./editor.md) を参照。
特定シーン・状態を URL／コードで再現する開発者向けの手順は [デバッグガイド](./debugger.md) を参照。

## TUI版スプラッシュ

TUI版は `tui-config.toml` の `[splash]` で起動画面を設定できます。

- `splash.logo_image`: `event_image.assets_dir` を基準にしたロゴ画像の相対パス。設定すると、画像をキャンバス全幅に contain 表示し、画面に収まらない縦方向は ↑ / ↓ でスクロールします。
- `splash.scroll_ease_ms`: ↑ / ↓ のスクロールアニメーション時間（ミリ秒）。`0` にすると即時移動します。
- ↑ / ↓: 画像ロゴを1行ずつ上下にスクロールします。最上端・最下端を越えて移動することはありません。
- `logo_image` が正常に読み込めた場合は `splash.lines` は無視されます。
- `logo_image` の読み込みに失敗した場合は `splash.lines` のテキスト表示へフォールバックします。`lines` が空でも、空行と画面最下部の共通操作フッター（下記）は表示されます。
- 画面最下部には、起動直後のスプラッシュ画面から通常プレイまで常時、操作キー一覧のフッターを表示します（#587）。旧仕様の起動時「Enter / Space で開始」単独表示は廃止し、`Enter/Space 次へ / ↑/↓ 選択 / A オート / S スキップ / B バックログ / C 設定 / Q/Esc 終了` を同格で常時提示します。これにより初見でも設定 (`C`) やバックログ (`B`) の存在を確認できます。ただし「常時」は固定キャンバス（130 列 x 33 行）以上の端末に限る — それ未満の端末では（ロゴ画像モード・テキストモードいずれも）フッターを含む通常のゲームUI自体を描画せず、「端末を広げてください」という案内メッセージにフォールバックします（TUI版はGUI版のような動的リサイズを行わない設計判断のため。セルフレビューで発覚: 修正前はテキストモードだけこのガードが欠けており、狭い端末でフッターの一部だけが欠落表示されていた、#587）。

## TUI版セーブ（#579）

TUI版はGUI版のような複数スロットのメニュー式セーブ/ロードは持たず、**自動クイックセーブ/自動クイックロードのみ**を持つ。

- シーンが切り替わるたびに、現在のフラグ・シーンID・既読行を自動でファイルに保存する（選択肢の有無に関係なく毎シーン）
- BGM・イベント絵・暗転状態など、着地シーンより手前で宣言され着地シーン自身では再宣言されず前のシーンから引き継いでいるだけの状態も、保存時点の値としてあわせて保存・復元する
- 起動時に保存ファイルがあれば自動で読み込み、前回の続きから再開する
- 保存先は `--config` で指定したconfigファイルと同じディレクトリ（`--config`未指定時はカレントディレクトリ）
- 保存済みのシーンIDが原稿変更等で見つからない場合は、フラグ・シーン位置・既読行のいずれも復元せず、通常の初期状態から開始する（部分的な復元による不整合を避けるため）
- 書き込みに失敗した場合も進行は止まらない（サイレントに継続）
- 保存ファイル名は `.name-name-tui-quicksave.json` 固定。エンジン本体のリポジトリの `.gitignore` には登録済みだが、保存先はゲームプロジェクト（原稿）側のリポジトリ内になることが多いため、開発者は自分のゲームリポジトリの `.gitignore` にもこのファイル名を追加し、個人のプレイ状態を誤ってコミットしないようにすることを推奨する
- `--new-game`（#622）: 起動時にこのフラグを付けると、既存のクイックセーブファイルの有無に関わらず必ず原稿の先頭（entry_scriptの最初のシーン）から開始する。フラグが立っている場合、既存のクイックセーブファイルは削除してから起動する（以後は通常起動でも今回の新規開始が自然に「続きから」として引き継がれる）。ファイルが存在しない場合はエラーにならない。**削除に失敗した場合（権限エラー等）は、他の自動セーブ処理と異なりfail-softにせずエラーとして起動を中断する**（新規開始の要求を黙って無視しないため）
- `--debug-scene <sceneId>` / `--debug-unlock-all`（#652）: デバッグ用の起動オプション。任意のシーンから直接開始・選択肢ロックの強制解放ができる。詳細は[デバッグガイド](./debugger.md)の「TUI 版」節を参照

## ノベルプレイヤー

### キーボードショートカット

| キー | 動作 |
|---|---|
| Space | 次のテキストへ |
| Enter | 次のテキストへ |
| → (右矢印) | 次のテキストへ |
| ← (左矢印) | 前のテキストへ |
| S | セーブメニューを開く |
| L | ロードメニューを開く |
| B | バックログの表示/非表示を切り替え |
| Escape | 開いているオーバーレイを閉じる |

### マウス・タッチ操作

| 操作 | 動作 |
|---|---|
| クリック / タップ | 次のテキストへ |
| 黒帯（letterbox/pillarbox の余白部分）をクリック / タップ | 次のテキストへ（canvas の外側でも同じ動作。canvas 自身のクリック判定が届かないため #467 で追加） |
| シークバー帯をタップ / ドラッグ | その位置にジャンプ（同時にスライダが前面に出て下部ボタンが一時退避。シーク操作はテキスト送りを兼ねない） |

### テキスト送り

ダイアログ（台詞）とナレーションはカノソ方式で表示される:
1. テキストが一瞬で全文表示される
2. クリック / Space / Enter / → で次のテキストに進む
3. ← で前のテキストに戻る

**終劇（"to be continued..." の画面）は行き止まり**: 終劇に達すると、← キーでもシークバーでも物語へ巻き戻せない（意図した仕様、#815）。続きを見るには「はじめから」「つづきから」などで始め直す（シーン転換・ロードで終劇は解除される）。

背景変更・BGM再生・暗転などの演出イベントはユーザー操作なしで自動実行される。

作品の frontmatter `dialog_style: "novel"`（全画面ノベル）では送りが**文単位（息継ぎ単位）**になる (#292)。クリック / タップは句点・感嘆符・疑問符で割った文を 1 つずつ送り、既出の文は同じページに溜まる。文末の右に出るクリッカーは種別で形が違う: `▼` は同じページに次の文がある（続き送り）、`❯` はそのページの最後の文＝次のクリックで改頁。ページが尽きたら次のテキストへ進む。

さらに、脚本の本文中に書かれた**単独行 `---`** は手動の強制改頁になる (#292 Phase 2)。自動改頁（収まる行数で区切る）より早くページを切りたいときに作者が入れる印で、`---` を境に続きの文が新しいページの先頭から始まる。`---` を含まない脚本は文単位送りの挙動そのまま（変化なし）。

`dialog_style: "adv"`（既定・下部 ADV 箱）は従来どおり 1 クリックで次のテキストに進む（`---` の手動改頁・文単位送り・クリッカー 2 種は novel 専用）。

### セーブ/ロード

#### セーブ

1. **S** キーを押す（またはセーブボタンをクリック）
2. セーブメニューが表示される（3スロット）
3. 保存したいスロットをクリック
4. 現在の状態がスロットに保存される

#### ロード

1. **L** キーを押す（またはロードボタンをクリック）
2. ロードメニューが表示される
3. 読み込みたいスロットをクリック
4. 保存時の状態が復元される（背景・BGM・立ち絵・テキスト位置）

#### データのエクスポート/インポート

セーブデータを JSON ファイルとしてエクスポート・インポートできる。別のブラウザや端末にデータを移行する場合に使用。

#### クイックセーブ/クイックロード

**F5** キーで現在の状態をクイックセーブ（3スロットとは独立した専用スロット）、**F8** キーでクイックロードする（#142）。結果は画面のトーストで知らせる（「クイックセーブしました」「クイックロードしました」。選択肢の表示中・待機中・終劇後（セーブのみ）は「この場面ではセーブ／ロードできません」、場面転換中は「場面転換中のためセーブ／ロードできません」）。

#### 自動クイックセーブ/自動クイックロード（#578）

プレイヤー画面では、シーンに入って最初の本文を表示した時点で自動でクイックセーブする（冒頭が選択肢やジャンプだけのシーンは、その先の本文で保存）。次回そのプロジェクトを開いたとき、クイックセーブデータがあれば自動で読み込んで前回の続きから再開する（`?scene=` 等の明示的な起点指定や、fluid 再マウント時の引き継ぎがある場合はそちらが優先される）。手動の F5/F8 クイックセーブと同じ専用スロットを共有する。エディタのプレビュー画面（プロジェクト未確定）では動作しない。

### バックログ

1. **B** キーを押す
2. これまでに表示されたダイアログ・ナレーションの一覧が表示される
3. **↑** / **↓** キーまたはマウスホイールでスクロール
4. もう一度 **B** を押すか **Escape** で閉じる

### シークバー（シナリオスライダ）

ゲーム全体の進行位置を確認・操作できる水平スライダ。下部の丸ボタン（S/A/⚙/D）の**中央を貫く高さ**に置かれ、通常時は控えめに表示されてボタンより背面に見える（ボタンの円を貫くライン）。

- バーの塗りつぶし部分が現在位置を示す
- フィル／つまみの色は既定で水色（`#a8dadc`）。frontmatter `seekbar_color: "#rrggbb"`（#440）で作品ごとに変えられる（例: theo-hayami の金 `#b8934f`）。トラック背景（暗いグレー）は据え置き
- スライダをタップ / ドラッグして操作すると、スライダが**前面に出て主役になる**: つまみが拡大し、影が付き、重なっている下部丸ボタンは opacity でフェード退避してスライダ操作を邪魔しない（マウスを近づけただけでは前面化しない。実際に操作した時だけ）
- バーの任意の位置で操作すると、その位置にジャンプする（背景・BGM・立ち絵などの状態も自動的に復元される）。シーク操作は「次のテキストへ」を兼ねない（同じタップで 1 つ進んでしまわない）
- しばらく操作がないか、ほかを操作すると、スライダは控えめな表示に戻り、丸ボタンが再表示される
- **終劇後はスライダが無効表示になる**（つまみが消えて薄いバーだけが残り、タップ/ドラッグ/キーを受け付けない。終劇は行き止まりのため巻き戻せない、#815）。ロードや場面転換で終劇が解除されると通常に戻る
- 暗転（[暗転] / blackout）中はスライダを表示しない（黒画面の上に薄い線が残らないようにするため）
- 動画書き出し中はスライダを表示しない（録画に焼き込まれないようにするため）

### 選択肢

選択肢が表示されたら:
1. 選択肢のボタンが画面に表示される
2. クリック / タップで選択
3. 選択に応じてフラグが設定され、対応するシーンにジャンプする

選択肢が多くて画面に収まりきらない場合だけ、選択肢一覧は画面内でスクロールできる表示になる。マウスホイールまたはタッチドラッグで上下に動かし、すべての選択肢を確認して選べる。少数の選択肢は従来どおり中央寄せで表示される。

脚本側の設定によっては、一部の選択肢が「ロック」されて表示されることがある（#591）。ロック中の選択肢は暗めの配色で見分けがつき、クリック/タップしても選択できない。特定のフラグが立つ（他のルートをクリアする等）と自動的にロックが解除される。

同様に、既にクリアしたルートに対応する選択肢は「完了」扱いの見た目（ロックとは別の暗めの配色）になることがある（#594）。ロックと違いクリック/タップで通常どおり選択でき、見た目だけがそのルートをクリア済みであることを示す。プロジェクトが任意アセット `assets/images/read-icon.webp` を用意していれば、完了扱いの選択肢や、既に一度選んで読み進めたことがある選択肢はテキストの上にそのアイコンも表示する（未配置/取得失敗時は配色のみ、#658）。まだ一度も選んでいない選択肢についても、プロジェクトが任意アセット `assets/images/unread-icon.webp` を用意していれば同様にアイコンを表示する。ロック中の選択肢もこの2種のアイコンの対象になり、配色だけがロック専用になる——ロックは「読むことすらできない」状態を表すだけで、未読/既読の状態自体には影響しない（#604）。

選択肢の文言が長い場合、ボタン内のテキストは自動的に折り返され、ボタン枠からはみ出すことはない（折り返しで行数が増えた分、ボタンの高さも自動的に広がる、#658）。

`[選択]` を持たないまま脚本の記述が尽きた場合は、選択肢経由の終劇と同じ処理が流れて画面中央に "to be continued..." が表示され、BGM 停止・背景/立ち絵フェードとともに物語が終わる（従来は無反応で固まっていた、#470）。

### オーバーレイの閉じ方

セーブメニュー・ロードメニュー・バックログなどのオーバーレイは **Escape** キーで閉じられる。

### フルスクリーン表示

画面右上隅（右下の ⚙/A/S/D ボタン列とは別位置）にフルスクリーン切り替えボタンがある (#468)。押すとゲーム画面全体（letterbox 込み。ヘッダ等は含まない）がブラウザのフルスクリーン表示になり、もう一度押すか **Escape** で解除される。見た目はせおはやみ (theo-hayami) のトグルボタンと同じデザインで、右上隅の小さな金色の三角（44x44 のタップ領域の隅に 20x20 で表示）。通常時は薄く、hover/タップ直後は濃くなる（タップ後 2.8 秒だけ濃さを保つ余韻あり）。三角の向きで通常表示中/フルスクリーン中を示す。非対応ブラウザや拒否された場合は何も起きず通常表示のまま。

### デバッグ HUD（D ボタン）

デバッグが有効な作品（frontmatter `debug_enabled`）とエディタでは、右下ボタン列に **D** ボタンが出る。押すとデバッグ HUD パネルが展開し、再押しで畳む。パネル右上の **×** ボタンでも閉じられる（全体化＝フルスクリーン中に D ボタンが HUD の裏に回っても、パネル内から確実に閉じられる）。

## RPG プレイヤー

PixiJS ベースのタイルマップ RPG モード。`gameData` を渡さない場合はサンプルデータが読み込まれてそのまま動作する。

レンダラーはシーン側の `[view=...]` 指定に応じて切り替わる:
- `[view=topdown]`（デフォルト）: 見下ろし型（TopDownRenderer）
- `[view=raycast]`: 一人称レイキャスト型（RaycastRenderer）

### 見下ろし型（TopDown）のキーボード操作

| キー | 動作 |
|---|---|
| ↑ / W | 上に 1 マス移動 |
| ↓ / S | 下に 1 マス移動 |
| ← / A | 左に 1 マス移動 |
| → / D | 右に 1 マス移動 |
| Enter / Space | 正面の NPC に話しかける / 会話ウィンドウを閉じる |

**エンカウントと戦闘（#784）**: マップにエンカウント設定（`[エンカウント率]` / `[エンカウント群]`）があると、1 歩ごとの抽選に当たった時点で戦闘画面（Raycast と同じ `BattleScreen`）に切り替わる。戦闘の見た目・コマンド窓・ATB などの設定は frontmatter（`battle_layout` / `sprite_style` / `window_style` / `battle_atb` / `battle_command_layout` など）を Raycast と同じ書き方で共有する。

- 戦闘中はフィールドの移動・会話・タップ／スワイプ・エンカウント抽選が止まる（矢印キーで裏のプレイヤーが動くことはない）
- 勝利・逃走・全滅のいずれでも戦闘画面が閉じ、元の位置のフィールドに戻る。戻った直後の 3 歩はエンカウントしない（クールダウンは戦闘終了時にセットする）
- エンカウントした瞬間に押しっぱなしだった矢印キーは、戦闘側でも戻ったフィールド側でも一度離すまで無視する（誤爆防止）
- 設定画面（Ctrl+,）を開いている間は、フィールドも戦闘のキー操作も受け付けず、ATB の時間も進まない。ウィンドウがフォーカスを失う（blur）と押下状態は捨てられる
- エンカウントした歩のタイル踏み込みトリガーは、戦闘が終わってから発火する（勝利・逃走のみ。全滅では発火しない）

### レイキャスト型（Raycast）のキーボード操作

一人称視点。連続移動＋回転でファーストパーソン・ダンジョン探索感覚。

| キー | 動作 |
|---|---|
| ↑ / W | 前進 |
| ↓ / S | 後退 |
| ← / A | 左回転 |
| → / D | 右回転 |
| Q | 左ストレイフ（真横に移動） |
| E | 右ストレイフ（真横に移動） |
| PageUp | 上を見る（pitch +、最大 ±0.4 rad ≒ ±23°） |
| PageDown | 下を見る（pitch −） |
| Z | ジャンプ（最高約 0.375 タイル分、滞空 0.5 秒。空中での再ジャンプ不可） |
| Enter / Space | 正面タイルの NPC に話しかける / 会話ウィンドウを閉じる |

### 移動と通行判定

- **見下ろし型**: 移動はグリッド単位。1 マス移動につき約 150ms のアニメーションが入り、その間は次の入力を受け付けない
- **レイキャスト型**: 連続移動（約 3 タイル/秒、回転 約 3 rad/秒）。キーを押し続けると移動し続ける
- 木（TREE）と水（WATER）のタイル、および NPC のいるタイルには入れない（両モード共通）
- レイキャスト型では XY 分離で壁ずり衝突する（壁に斜めに当たると沿って滑る）
- マップ端を越えることもできない

### 会話

プレイヤーの向いている先のタイルに NPC がいるとき、Enter / Space で会話が開始し、画面下部にウィンドウが表示される（NPC 名と本文）。再度 Enter / Space で閉じる。会話ウィンドウ表示中は移動入力を受け付けない。両モードで同じダイアログ UI を使う。

メニューの「はなす」から会話を開始した場合、選択した tap が直後の canvas tap として canvas に届いてダイアログが即時に閉じる/進む事故を防ぐため、二段構えの防御を入れている:

1. `handleMenuSelect` の入口で `suppressNextTouchTap(DIALOG_JUST_SHOWN_GUARD_MS)` を再延長する（同一 PointerEvent シーケンス内の漏れ tap を確実に弾く一次防御）
2. `handleTap` 側で `dialogBox.isJustShown(DIALOG_JUST_SHOWN_GUARD_MS)` が真のときは close / advance / typewriter skip を全て無視する（時刻ベースの保険、suppressNextTouchTap が漏れたケース）

ガード幅は `DIALOG_JUST_SHOWN_GUARD_MS = 400 ms`（`tapMaxDuration = 350 ms` と `suppressNextTouchTap` のデフォルト 250 ms を覆える値）。EventRunner の Dialog / Narration コマンドで `dialog.show` された直後も同じガードが効く（DialogBox 側で時刻を持っているため）。

### スマホ・タッチ操作（両モード共通）(#178)

オンスクリーンの仮想パッドは出さず、ジェスチャだけで操作する:

| 操作 | 動作 |
|---|---|
| スワイプ ↑ | TopDown: 上に 1 マス移動。Raycast: 正面に 1 タイル前進 |

### ミニマップ (#149)

**Raycast モード（一人称視点）** の画面右上に **2D 全体俯瞰ミニマップ**を半透明で重ねる。一人称で迷子にならないための助け。

- プレイヤーは **赤い三角形**（向いている方向の頂点が前向き）
- NPC は NpcData の色で **小さな丸ドット**

### 戦闘プロト (#173, Phase 1)

Raycast モードで DQ4 メニューの **「しらべる」** をタップすると、テスト用の戦闘プロトが起動する（暫定経路、本来は #172 確率エンカウントで自動発火）。

レイアウト: フィールドを半透明黒で暗くした上に、敵スプライト枠（中央上部、現状はテキストのみ）+ 4 コマンドウィンドウ（たたかう / じゅもん / どうぐ / にげる）+ 戦闘ログ（最新 4 行）を重ねる。Undertale 風 + DQ1/DQ5 風（背景フィールドが透けて見える）。

**レイアウトの切替（#736）**: frontmatter の `battle_layout:` で選ぶ。未指定・`front` は上記の Undertale 風（味方は先頭 1 人のみ）。`side` は FF 系サイドビューで、次の構成になる。

- 上に **ログ帯**。行数は敵の数で変わる（敵 1 体=2 行・2 体=3 行・3 体以上=4 行。画面が低くて戦場が潰れるときは減らす）
- 中央の戦場は左が敵群・右が味方全員。複数体は千鳥（2 行以上なら奇数行を横にずらす）に並び、列数は「3 体まで 1 列・4 体以上は 2 列」を下限に、敵ラベルの HP 行が読める大きさ（約 64px 以上）になる最小の列数を選ぶ（低い横長画面ではラベルの可読性を優先して千鳥なしの 1 行になる）。各敵の下に **名前と HP のラベル**（背景が写真でも読めるよう文字に縁取り付き。長い名前は「…」で省略。画面が極端に小さく名前も HP も読めない幅になるときはラベルだけを省き、スプライトは残す）。**味方が 1〜3 人でも、4 人のときと同じ斜め一列の枠（位置・大きさ）と下パネルの高さのまま**で、上の枠から順に入る（空き枠は何も描かない・人数でキャラの大きさも位置も変わらず、立ち絵の縦横比が人ごとに違っても枠は動かない（後衛の有無を除く: 後衛が 1 人でもいると右側の余白を確保するので、全員の位置・大きさ（小さい縦長画面では先頭で約 15%）と敵の領域が変わる）（絵は枠に収まる縮尺で描かれ、横に広い絵は少し小さくなる） #813。5 人以上は人数ぶん）
- 下に **コマンド（2x2 のタップ）** と **味方全員分の HP/MP パネル**（名前・HP・MP の列を 4 人でそろえ、HP・MP は見出し「HP」「MP」と「/」の位置もそろう。幅が狭い画面では MP を省き、さらに狭いと見出し → HP の最大値の順に省いて、名前を最低 3 文字ぶん残す）
- 戦闘中に画面サイズが変わると、`front` / `side` とも戦闘画面が新しいサイズに追従して再配置される
- 行動できるのは先頭の生存者のみ（全員行動は #205 待ち）
- `[モンスター]` / `[パーティ]` の `スプライト` を表示する（未指定・読み込み失敗は色四角）

`battle_background:` に画像パスを書くと、フィールドを暗くする半透明黒の代わりにその画像を全面に敷く（`front` / `side` 共通。読み込めないときは従来どおり半透明黒）。

**スプライトの表示スタイル（#737）**: frontmatter の `sprite_style:` で選ぶ。未指定・`none` は素材そのまま。`acrylic` は実写背景の上でもキャラ境界が読めるよう、`side` のスプライトを「アクリルスタンドに印刷された 2D」風に描く（スプライトの輪郭を外側へ広げた透明なアクリル板（ごく薄い白〜水色の透明な面で背景が透け、縁は細い明るいリムで左上の光側を強く、斜めの鏡面ハイライトが入る。板は長辺 192px の作業解像度で作って mipmap で拡縮するのでなめらか）、透明アクリルの台座（ごく薄い面・側面の厚み・縁のハイライト・板の差し込み口）と柔らかい接地影、地面に右奥へ倒れるキャラ本体の影（板は台座の差し込み口の高さで水平に切れる。キャラの足元は差し込み線より少し上に浮き、板は差し込み線まで届いて台座に刺さって見える。`spriteLiftRatio=0` でも足元は台座の中心でなく差し込み線に置かれるので、#802 以前の見た目（スプライトが約 0.28×台座の縦半径だけ下）には戻らない。浮き量 0 は「差し込み線に接する」という意味。#802）。紙人形輪郭（白い余白で囲む）とは逆に、板は透明）。素材ファイルは加工せず描画時にかける。画像が無い枠（色四角）にはかけない。`front` は敵・味方の画像を描かないので変化しない。スプライト画像は**足元に余白を残さないタイトな切り抜き**にすること（スプライトの外接矩形の下端を台座の中心に合わせるため、足元に透明な余白があると、意図した浮き量より余計にキャラが台座から浮く）。

**ウィンドウの配色テーマ（#744）**: frontmatter の `window_style:` で選ぶ。未指定・`dark` は従来どおりの半透明黒。`ff-blue` は FF6 風に、ログ・コマンド・ステータスのパネルを青い**帯状**グラデーション（上=明るい青 → 下=濃い紺。滑らかでなく段差のある横縞）で塗り、パネルの角は dark と同じ角丸で、白枠もそのまま角丸、文字は白に黒い影を付ける。色だけが変わり、パネルの大きさや配置は変わらない。

**戦闘背景のトーン調整（#753）**: `battle_background:` で背景画像を敷いているとき、既定では背景の彩度と明度を表示時に落として、キャラ・敵が浮き上がるようにする（画像ファイルは変えない。キャラ・敵・パネル・文字には影響しない）。素材のまま表示したいときは frontmatter に `battle_background_tone: off` を書く。背景なしのときは無関係。

**戦闘背景の被写界深度風ぼかし（#753）**: frontmatter に `battle_background_dof: on` を書くと、背景の下側（手前）を下へ行くほど強くぼかし、上（水平線側）はくっきり残す（既定は `off`＝ぼかさない）。キャラ・敵・パネル・文字はぼかさない。`battle_background_tone` とは独立で、両方 `on` にもできる。背景なしのときは無関係。

**戦闘ログの 1 文字ずつ表示（#755）**: frontmatter に `battle_log_typewriter: on` を書くと、戦闘ログ（メッセージ）に新しく積まれた行だけが 1 文字ずつ表示される（既定は `off`＝従来どおり即時表示）。表示済みの行は即時表示のまま。タイプ中にコマンドかログ帯をタップすると、まず全文が即時に表示される（そのタップではコマンドは実行されない。もう一度タップするとコマンドが選ばれる）。**ATB（`battle_atb: on`）のときは例外**で、コマンドのタップは全文表示に使わずそのままコマンドを実行する（時間が流れていて空振りさせないため）。全文表示はログ帯のタップだけ。

**戦闘の奥行き（#747）**: `side` のとき、frontmatter に `battle_perspective: 0.8`（0〜1。既定 0＝平面）を書くと、奥の行ほど小さく・上に、手前ほど大きく・下に描いて床に立つ見た目になる。`battle_horizon: 0.3`（地平線の高さ。画面高さに対する比、既定 0.3）で地平線の位置を決める（地平線が低いほど奥の縮み方が大きい）。敵ラベル・acrylic の台座と影も縮尺に追従し、奥→手前の順に重ねる。`battle_foreground: bg/fg.png` で、スプライトより手前（パネルより奥）に透過 PNG の前景を敷ける。未指定は従来どおり（平面）。

**ATB（#205）**: frontmatter に `battle_atb: on` を書くと、戦闘が FF5 風の ATB 方式になる（既定は `off`＝従来ターン制）。味方・敵とも、素早さ（AGI）に比例した速さでゲージが溜まり、満タンになった順に行動する。ゲージが満タンになった味方は、溜まった順に 1 人ずつコマンド（たたかう / じゅもん / どうぐ。じゅもん / どうぐの一覧は `battle_command_layout: cross` のとき開く。下の「候補窓」参照）を出す（誰の番かは、そのキャラのアクスタの頭上の白い下向き三角「▼」〔板・台座ごと動き、画面の大きさに合わせて大きさが変わる。パーティが4人未満の空き枠と倒れたキャラには出ない〕と、名前の左の「▶」〔名前の直前に小さく置き、どの画面幅でも枠の線の中心から 4px 以上、名前の列（front は 1 行の文字の概算幅 260px との比較で判断）に余裕がある画面では最小の名前幅を割らない範囲で最大 8px 離れる。線の内側から見た隙間は 3〜7px。front では ATB 棒の左端も名前の左端にそろう〕・名前の黄色で分かる。各ステータス行の右端の短い棒が ATB ゲージ）。敵はゲージが満タンになると自動で行動し、狙いは生きている味方からランダムに選ぶ。AGI が同じで同時に満タンになったときの順は乱数。**にげるはゲージが溜まっていなくてもいつでも選べる**（失敗すると、コマンド待ちの味方、いなければゲージが最も溜まっている味方のゲージが空に戻る）。`battle_atb_mode:` で進み方を選ぶ: `wait`（既定・**待機**）= コマンドを選んでいる間は時間が止まる（`side` で候補窓が使えるときは、じゅもん・どうぐの一覧や対象選択の窓を開いている間だけ止まる。FF5/6 と同じ）/ `active`（**アクティブ**）= 選んでいる間も敵のゲージは進む。ステータス欄は名前・HP・MP の列を味方全員でそろえ（HP・MP の数値は右寄せ）、ゲージは行の右端に数文字ぶんの短さで置く（#745）。

**コマンド窓の配置と名前（#204）**: `side` のとき、frontmatter `battle_command_layout: cross` で FF6「短縮」風の十字配置になる（上=たたかう・左=じゅもん・右=どうぐ・下=にげる。既定は `grid`＝2x2 で従来どおり）。`cross` では**矢印キー（↑←→↓）1 押し**でその方向のコマンドを決定できる（タップも使える。選べない局面では無視する）。ログを 1 文字ずつ表示している間（`battle_log_typewriter: on`）は、最初の 1 押しは全文表示だけで、次の 1 押しでコマンドが決まる（ATB のときを除く）。エンカウントした瞬間に押しっぱなしだった矢印キーは、一度離すまで無視する（誤爆防止）。設定画面（Ctrl+,）を開いている間は戦闘のキー操作を受け付けず、ATB の時間も進まない。戦闘中は矢印キーでフィールドのキャラクターは動かない。`battle_command_labels: attack=斬る, spell=魔石` のように、コマンドの表示名をゲームごとに差し替えられる（id は `attack` / `spell` / `item` / `escape` 固定・部分指定可・省略は既定の日本語）。

**コマンドの構成を変える（#873）**: frontmatter `battle_commands: skill, spell, item, escape` のように、使うコマンドの id を並べた順に出せる（id は `attack`＝たたかう / `skill`＝わざ / `summon`＝しょうかん（#889。装備中の魔石の召喚獣を呼ぶ。1 人 1 バトル 1 回。候補窓は「わざ」と同じ）/ `spell`＝じゅもん / `item`＝どうぐ / `escape`＝にげる。未指定は従来の `attack, spell, item, escape` で変わらない）。「たたかう」を無くして「わざ」に置き換える使い方ができ、基本の攻撃は魔法メニューの無属性ダメージ魔法にする、といった作りになる。並べた順が配置の順で（`grid` は左上から右下、`cross` は 上・左・右・下）、`cross` の矢印キーも位置で決まる（`skill, spell, item, escape` なら ↑=わざ・←=じゅもん・→=どうぐ・↓=にげる）。`cross` は 4 つのときだけ有効（それ以外の個数は `grid`）。表示名は `battle_command_labels: skill=刀` のように差し替えられる。「わざ」は「じゅもん」と同じ候補窓（`grid` でも `cross` でも）が開き、中身はメンバー定義の `わざ: <特技 id>`（`[特技 id]` に定義した特技。複数行可）と、**装備中のどの装備品の `わざ:` も（#207。武器でも防具でも。メンバーの `わざ:` の後ろに重複なく足される。外せば消える）**。MP は使わず、対象は特技と同じ（`相手単体` / `相手全体` / `仲間単体` / `仲間全体` / `自分`）。敵の通常攻撃は残り、敵の条件 `受けた=物理` は通常攻撃に加えて「わざ」を受けたときにも成立する。

**候補窓（じゅもん・どうぐ）と対象選択（#204）**: `side` のとき（配置は `grid` でも `cross` でもよい。#806 で grid にも拡張。grid ではコマンドをタップして開き、開いたあとは矢印・Enter・Escape も使える。cross の矢印キーによるコマンド決定は従来どおり cross のみ）、呪文などが渡されていれば「じゅもん」（と、#873 が足りていても何も出ない）。呪文を決定すると対象選択に移り、**手の形のカーソル**が出て、指されている者（味方・敵。全体なら全員。蘇生の呪文では倒れた味方）のアクスタの頭上にも同じ「▼」が出る（対象選択の窓が開いている間は、手との二重表示で誰が対象か分からなくなるので、番の味方の「▼」は隠れて対象の「▼」だけが出る。窓を閉じると番の味方の「▼」が戻る。「▼」の位置は基本の絵の頭上に固定で、ポーズが変わっても上下しない。最上段のキャラで上端のログ窓にかかるときは、窓の下端の少し下まで下がって窓に隠れない）。単体の呪文は手が 1 本で、↑↓で指せる者の間を巡る。手が立つ側（敵か味方）は呪文の対象（`敵単体` / `味方単体` など）で決まり、←→では切り替わらない。指せるのは生きている者だけで、倒れた味方を指せるのは蘇生の呪文（効果 `revive` / ザオリク）だけ（このときは倒れた味方だけ）。対象選択の間は、下の一覧は隠れて敵・味方の絵を覆わない。全体の呪文は対象側の全員に手が同時に立つ。決定で呪文を使い、MP を消費する。**操作**: 矢印 = カーソル移動 / Enter または Z = 決定 / Escape・Backspace・X = キャンセル（一つ前の窓に戻る。窓が開いていないときの Enter・Escape は何もしない）。タップでは、行をタップで決定・手の指す対象をタップで確定・窓の外をタップでキャンセル。画面の下端の余白には、いまの局面の**操作の案内**が常に出る（コマンド選択中=タップ〔cross は矢印キーも〕、一覧=↑↓・Enter/タップ・Esc/窓の外をタップ、対象選択=↑↓〔単体のみ〕・Enter/タップ・Esc。画面が狭いと短い文に、さらに狭いと出さない。一覧窓が下端の余白まで伸びて文と重なるときは、窓の横の空きへ寄せ、置けなければ短い文→出さない。そのため縦長のスマホ（360×640 など）の一覧の局面など、狭い画面では案内が出ないことがある。案内は候補窓のデータがある画面にだけ出て、メニューの無いゲームは従来どおり何も足さない）。一覧が窓に収まらないときは、窓の上端・下端の余白にある▲▼の帯（記号の上でも可）をタップすると 1 行ずつスクロールする。一覧窓は背景が不透明で、幅はコマンド窓と同じを基本に、名前が 7 文字までは省略されずに読める幅を下限にする（縦長の画面でコマンド窓が狭いときに広がる。8 文字以上の名前は 6 文字 + 「…」）。ただし右端は味方ステータス欄の HP 列の左で止め、HP の数字を途中で切らない（名前列・▶が隠れるのは許容）。見える行は最大 4 行（高さは行が少なくてもコマンド窓の外形〔枠線の分まで〕全体を覆い、余白は下側）。**既知の制約**: 窓はコマンド窓の真上に出るので、画面によっては下の絵や欄に重なる。実測（味方 4 体・敵 3 体）: 800x450・640x360 では左下の敵の名前・HP ラベルの 7〜20%（敵の絵はほぼ重ならない）。縦長（360x640・320x568）では窓幅 205px で味方のステータス欄の名前列を約 29〜37% 覆う（絵・ラベル・HP 列には重ならない）。320x240 では敵の絵の約 42% に重なる。1280x720 はほぼ重ならない。手のカーソルは人差し指を伸ばした 14x8 ドットの絵で、敵は右から左向き・味方は左から右向きに出る。呪文は、パーティメンバーの `習得`（`Lv4 ホイミ` など）のうちそのレベル以下のもので、`[呪文 ID]` に定義があるものが、習得の並びで出る。「どうぐ」の一覧は、所持品の仕組みができるまで本編では何も渡されないので従来どおり何も起きない（battle-sample では `items` で試せる）。`front`、または呪文が 1 つもないときは、これまでどおり「じゅもん」「どうぐ」は何も起きない。呪文の効果の演出（動き）と、前衛・後衛の入れ替え操作は今後の対応。

**召喚獣の登場（#750）**: `battle_presentation: ff` のとき、`[召喚獣]` を参照する魔石の「しょうかん」・味方の「わざ」（`召喚獣id` つきの特技）を使うと、画面の中央に召喚獣の絵（`画像:`）が現れて消え、名前の札が添えられる。効果の数字は絵が出そろってから出る。`想像: はい` の召喚獣は、その間だけ戦場全体が暗い寒色に沈む（現実の戦闘と見分けるための演出。いいえなら見分けが付かない）。画像が無い・読めないときは名前の札だけ。召喚獣を使わないゲームは何も変わらない。敵は召喚獣を呼ばない（召喚獣風の技は普通の特技で書く）。書式は spec の「召喚獣 (#750)」、サンプルは `/battle-sample.html?config=/battle-sample/summon.json`。

**戦闘のエフェクト重ね（#936）**: `battle_presentation: ff` の戦闘で、設定に宣言した詠唱・打撃・斬撃・魔法ヒットのコマ割りシートが、呪文の発動（使い手の手元）や攻撃・呪文の命中（対象の位置）に重なって再生され、終われば消える。宣言しないゲームは何も変わらない。段階1は設定 JSON（戦闘画面サンプル `/battle-sample.html?config=/battle-sample/effects.json`、フィールドサンプルの `battle.effects`）だけで、frontmatter からはまだ宣言できない。書式は spec の「戦闘のエフェクト重ね (#936)」。

**フィールドの感情吹き出し（#937）**: フィールドサンプルの設定 `emotions` に宣言した絵（！・？・… など）を、人物の頭上に一定時間だけ出して消す。歩行・当たり判定・エンカウントには関与しない（出ている間も歩ける）。段階1は設定 JSON とツールバーのボタン・`window.fieldSample.showEmotion`（開発用ページ）だけで、frontmatter `field_emotions:` と脚本 `[感情: 主人公, 種類]` の構文・解決は用意した（#943）が、フィールドへ届く実行経路は未接続で、通常のノベルでは `[感情:]` は無視される。書式は spec の「フィールドの感情吹き出し (#937)」。

**FF 式の戦闘演出（#745）**: frontmatter に `battle_presentation: ff` を書くと（`battle_layout: side` のとき）、戦闘が FF 式の演出になる（既定は `dq`＝従来のログ表示で絵は動かない）。たたかうと、行動する側が前へ踏み出して斬って元の位置へ戻り、受けた側は短くのけぞる（点滅はしない）。HP が 0 になると倒れ、対象の位置にダメージ数字（回復は緑・外れは `MISS`）が跳ねて消える。上の窓には呪文・アイテムの名前だけが中央に一度に出て、通常攻撃では何も出ない。従来ターン制では**演出が終わるまで次のコマンド（タップ・十字キー）は受け付けない**。ATB のときは本家 FF5/6 と同じく演出中もゲージが進み、敵の行動は順に再生され、行動可能になった味方は演出中でもコマンドを入力できる（行動は前の演出のあとに再生される）。勝敗が決まっても最後の演出を見せてから、メッセージ窓に「しょうり！」（全滅は「ぜんめつ…」）を中央寄せで出し、勝った側の victory ポーズを約 1.5 秒見せてから戦闘画面が閉じる。**勝敗の待機は dq 式にもある**（最後のターンのログを読ませる約 0.8 秒。`battle_log_typewriter: on` のときは最後のログのタイプ表示が終わってから数える）。待機中に画面をタップするか Enter / Space / Z を押すと飛ばして閉じる（待機が始まった直後の約 0.25 秒は受け付けない）。逃走成功はすぐ閉じる（#745 分割4）。各キャラの絵はマスタ定義の `ポーズ:` で局面ごとに差し替えられる（仕様は `docs/spec/markdown-v0.1.md`）。

**戦闘の開始・終了の画面遷移（#830）**: frontmatter に `battle_transition: ff` を書くと（見下ろし型・一人称どちらでも。既定は `none`＝戦闘画面が即座に開閉）、エンカウントで操作キャラ付近へ「ドゥン、ドゥン」と 2 段に分けてズームインしながら暗転し、真っ暗になったら戦闘画面が開く。戦闘が終わると（勝敗の待機のあと）画面が黒へフェードアウトし、フェードインでフィールドへ戻る。演出中は移動・メニュー・タップを受け付けず、戦闘終了時に押しっぱなしだった矢印キーは離すまで効かない。時間・ズーム量は仮の値（#803 の測定値で差し替え予定）。

**隊列（前衛・後衛）（#747）**: `side` のとき、`[パーティ]` の `隊列: back`（または `row: back`）で後衛にできる（既定 `front`）。後衛は味方の斜め一列（左上から右下）の位置から画面の右寄り（敵から遠い側）に半歩下げて描かれ、通常攻撃で**受けるダメージ・与えるダメージがどちらも半分**になる（呪文・アイテムは影響なし。端数は切り捨て・最低 1）。戦闘中の入れ替えはコマンド窓の Issue（#204）で扱う。**注意**: 従来ターン制の BattleEngine は攻撃側・被弾側とも `firstAlive(party)` の 1 人だけなので、後衛のダメージ半減は**先頭の生存者が後衛のときだけ**見える。ATB（`battle_atb: on`、#205）では全員がゲージ順に行動し、敵の狙いも生存味方からランダムなので、後衛の半減が常に見える。

| コマンド | 動作 |
|---|---|
| たたかう | DQ 式の通常攻撃。ダメージ = max(1, atk - def/2) + rand(0..atk/4) |
| じゅもん / どうぐ | Phase 1 では未実装ログのみ（パーティ #175 で本実装） |
| にげる | 50% で escaped、失敗で敵ターン（ATB では行動者のゲージが空に戻り、敵ターンは挟まない） |

戦闘終了（victory / defeat / escaped）で自動的に画面を畳む。経験値 / ゴールドは集計してログに出すが、レベルアップ判定は #175 まで保留。
