# 戦闘の検証ハーネス (#877 段階 3)

規則の組み合わせを総当たり・seed 固定のランダム合成で動かし、**壊れ**（進行不能・無限ループ・NaN・負 HP・maxHp 超過・ダメージ上限違反など）を一覧にする手動ツール。**検出のみ**で、上限の有効化・エンジンの修正・規則の変更はしない。

- 置き場: `frontend/src/game/battleHarness/`
- CI には入れていない（入れるかは未決）。通常の `npm test`（`vitest.config.ts`）にも総当たりは入らない。

## 使い方

```bash
cd frontend
npm run test:battle-harness                       # 総当たり（約 41,000 件・5 分弱）
HARNESS_RANDOM_COUNT=500 npm run test:battle-harness   # ランダム合成の件数を変える（既定 3000）
HARNESS_SEED=2 npm run test:battle-harness             # ランダム合成の seed を変える（既定 1）
HARNESS_SKIP=random,enemy-skill npm run test:battle-harness   # 族を省く
HARNESS_RANDOM_STATUS_COUNT=500 npm run test:battle-harness   # 状態を宣言したランダム合成の件数（既定 2000）
HARNESS_RANDOM_SCRIPT_COUNT=300 npm run test:battle-harness   # 脚本制御の戦闘のランダム合成の件数（既定 1000）
```

環境変数: `HARNESS_SEED` / `HARNESS_RANDOM_COUNT` / `HARNESS_RANDOM_STATUS_COUNT` / `HARNESS_RANDOM_SCRIPT_COUNT` / `HARNESS_SKIP`（`effect-matrix,enemy-skill,stack-order,reaction-chain,random,status-matrix,random-status,damage-condition,magicite,loot,script,random-script,equipment,job,summon`）/ `HARNESS_OUT`（出力先。既定 `frontend/battle-harness-out/`。git 管理外）/ `HARNESS_STRICT=1`（壊れがあれば失敗扱い。既定は一覧を出して成功）。

## 出力

`battle-harness-out/`（再現時は `battle-harness-out/replay/`）に 2 つ。標準出力にも `report.md` と同じ内容が出る。

- 件数の注記: 「要判断」は膠着だけがあるシナリオの数で、壊れと膠着の両方を持つシナリオは壊れに数える。そのため一覧の `stalemate` のシナリオ数より冒頭の要判断の件数が少ないことがある。
- `report.md`: 件数、族ごとの壊れ件数、**壊れ**（種類ごと・代表例つき）、**要判断**（`stalemate`: 行動は起きるが攻撃だけでは決着しない膠着）、**凄い組み合わせの候補**。
- `failures.json`: 壊れ・要判断のシナリオ（最大 5000 件）。seed・初期パーティ/敵・呪文/特技・操作列がそのまま入っているので、これだけで再現できる。

分類:

- 壊れ / 正常: 機械判定。違反が 1 件でもあれば壊れ。負の `damage` 範囲・負の `resist` による最大 HP 超過、同時全滅（敵も味方も HP 0）の victory と ATB キューの残骸は #877 で修正済み（負の量は 0 として扱い、負の `resist` は 0 に丸める。同時全滅は敗北優先）。残る要判断は膠着（`stalemate`）のみ。
- 凄い組み合わせ（強すぎ・許容）: **閾値を決めていない**。壊れでないシナリオの指標（1 行動の合計ダメージ・HP の減少量・回復量・ヒット数・バフ累積値）の上位を数値のまま並べるだけ。残す/潰すは人間が判断する。
- ダメージ上限違反は `damage` のヒットの量が 9999 超（`battleLimits.MAX_DAMAGE`）かで見る。`heal` は上限が未決のため検出せず、候補（`maxHealAmount`）に回す。`damage_full`（即死）は上限の対象外（hit に `instantDeath` が付き、数字は出ない）で、検出から除外し、HP 減少は `maxHpDrop` の候補に並ぶ。

検出する種類: `script-invariant`（脚本の状態の整合: 経過ターンが非負の整数・発動済みの添字が重複せず範囲内・参戦した味方が味方にいて重複しない・逃げた敵の HP が 0・`hpFloor` が 1〜最大 HP の整数。脚本の無い戦闘に脚本の状態・`interrupted`・`hpFloor` が出ない）/ `script-outcome`（脚本のシナリオが期待外の終わり方・ターン上限超え）/ `script-no-end`（終わるはずの脚本のシナリオが自動進行の上限まで決着しない）/ `non-finite`（NaN/Infinity）/ `unsafe-integer` / `negative-hp` / `negative-mp` / `hp-over-max` / `mp-over-max` / `damage-over-cap` / `hit-direction`（damage で HP が増える・量が負など）/ `bad-log-text` / `phase-mismatch`（勝敗と生存者の食い違い）/ `atb-invariant`（ゲージ 0..1000・キューは生存者のみで重複なし・フェーズ整合）/ `status-invariant`（宣言した状態の残りターンが 0〜99 の整数でない・倒れた者に残っている・`status` イベントが本人だけを対象にしていない）/ `damage-memory`（`ダメージ…` を書いた敵の記憶が直前の味方の行動の表示数字と食い違う。MISS・吸収のあとに前回値が残る等）/ `magicite-invariant`（魔石 #889: 通常攻撃の属性が 2 つを超える・召喚済みの印が真でない・同じ味方が 1 バトルで 2 回召喚した・召喚したのに印が立たない）/ `summon-invariant`（召喚獣の演出 #750: 演出を宣言していないシナリオのイベントに `summon` が付いた・宣言していない id・`skill` 以外のイベントに付いた・名前や id が空・画像/効果音が空文字や文字列でない・想像が真でない・向きが `left` でない・魔石が演出の元を持つのに召喚の記録に同じ id の演出が付かない）/ `loot-invariant`（`state.loot` が宣言した品だけか・レア枠の印が合うか・敵ごとに盗めた回数が上限内か・個数が 1〜99 の整数か・ドロップが勝利のときだけでぬすんだ品より後か）/ `lock`（HP・状態もイベントも変わらないまま進まない）/ `stalemate` / `event-flood` / `rng-budget` / `slow-op` / `exception`。

無限ループは「1 操作の乱数消費が 200 万回を超える」で止めて検出する（乱数を使わないループや同期的な無限ループまでは拾えない）。検出できないもの: エンジンが残すイベントは直近 30 件（`EVENT_MAX`）なので、1 操作で 30 件を超えて増えた分のヒットは検査されない。

状態異常 (#870) の永久の行動不能（毎ターン睡眠・昏睡を付け直す敵）は、壊れではなく膠着（`stalemate`、要判断）として拾う。エンジンは持続を 99 で頭打ちにし、行動不能の味方の手番を 1000 手番までで自動解決して制御を返すので固まらないが、付け直し続ける敵への歯止め（免疫など）は未決。従来ターン制は先頭の生存者しか行動しないので、先頭の長い行動不能は味方全体を止める（spec の「状態」）。

ATB の不変条件（ゲージ 0..1000・キューは生存者のみ等）と `lcg` は `battleEngineAtb.test.ts` にもあり、正本が 2 つになっている。統合は後続。

## 失敗の再現

```bash
HARNESS_REPLAY=battle-harness-out/failures.json HARNESS_REPLAY_ID='effect-matrix/e2/敵単体/resist-1/hp100' \
  npm run test:battle-harness
```

`HARNESS_REPLAY_ID` を省くとファイル内の全件を再実行する。単体のシナリオ JSON（`Scenario` 1 件）もそのまま渡せる。結果は `battle-harness-out/replay/` の `report.md` と標準出力に出る（`HARNESS_OUT` が読み込み元と同じディレクトリなら何も書き出さず、標準出力だけ）。コードからは `runScenario(scenario)`（`run.ts`）を呼ぶ。

## テスト

ハーネス自体のテスト（`*.test.ts`）は通常の `npm test` に入る（合成エンジンで NaN・負 HP・ロック・無限ループを仕込んで検出できること、正常な戦闘で誤検出しないこと、seed 固定の再現、失敗 JSON からの再現。実行は数秒）。総当たり本体は `harness.sweep.mjs` で、通常実行からは除外している。入口が `.mjs` なので tsc には掛からず、eslint も TS 用のルール（recommended）は効かない（`.mjs` は既定設定で走るだけ。型の無い node 入口の限界。`@types/node` が無いため `.ts` 化は見送り）。`HARNESS_RANDOM_COUNT` などの不正値と `HARNESS_SKIP` の未知の族名はエラーで止まる。
